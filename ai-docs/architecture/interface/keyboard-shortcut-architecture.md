# 快捷键管理架构

更新日期：2026-11-08。用户可见的按键清单见[快捷键](keyboard-shortcuts.md)，事件分层入口见[键盘路由](keyboard-routing.md)。本文说明快捷键的管理边界、状态优先级和逐键模块设计。

文档单一权威：`keyboard-shortcuts.md` 只权威维护用户可见键位清单；本文只权威维护逐键模块、上下文优先级和层间职责；`keyboard-routing.md` 仅介绍入口并链接到本页，不复制行为矩阵。Task 只记录范围与验收，不另维护一份键位表。

## 设计目标

快捷键是“焦点作用域 + 实体按键 + 当前交互上下文”共同决定的一次意图。相同按键在弹窗、命令输入、输入法、公式编辑和正文中可以有不同含义，但一次事件只能由当前最内层有效处理者执行。Qt/QML 负责把事件送到作用域入口，Rust Session 对依赖编辑状态的意图做领域裁决；布局只提供视觉几何。

编辑器快捷键统一由 `crates/caret-engine/src/editing/session/keyboards/` 管理。每个现有快捷键或语义独立的快捷键家族有具体处理文件；同一处理器可收纳只改变扩选/修饰状态的变体，像 Mod+Backspace 这种独立动作保留自己的 `mod_backspace.rs`。`keyboards.rs` 负责入口和事件分派。不要按编辑上下文新建 `math.rs` 之类的路由文件，也不要把按键优先级留在 `math_edit.rs`、app 或 QML。数学模块只提供编辑、移动和退出等领域操作，由对应快捷键处理文件决定何时调用。

窗口快捷键和控件本地快捷键仍分别属于窗口与焦点控件作用域，不并入编辑器 Session。当前实现仍在向逐键统一的边界迁移，现状差异列于下文。

## 一次按键的路由

```text
最内层弹窗 / 有焦点控件
        │ 未消费
        ▼
应用窗口快捷键（仅窗口动作）
        │ 正文画布获得焦点
        ▼
Qt QKeyEvent → 平台键映射 → 编辑器意图
        │
        ├─ IME 预编辑/提交：Qt 输入适配 + Rust composition 状态
        └─ Session 单次路由目标 → 命令输入 / 结构选区 / 数学编辑 / 正文
                                  │
                                  └─ 几何候选由 app 布局快照提供
```

事件处理者消费事件后不得让同一事件继续触发外层快捷键。打开、保存和缩放属于窗口级动作，仍放在 `qml/App.qml`；撤销/重做当前由窗口 Shortcut 发起，但画布编辑焦点下的状态优先级目标由 `mod_z.rs` 管理，其他控件焦点不进入编辑器 Session。控件自身的关闭、选择等动作由拥有焦点的控件负责；画布键位由 `document_canvas/keyboard.cpp` 映射。依赖命令行、选区、公式或文档结构状态的行为必须由 Rust 命令/Session 决定。

## 逐键模块

| 目标文件 | 键位 / 状态 | 职责 |
| --- | --- | --- |
| `escape.rs` | Escape；已有处理器 | 命令输入、IME、数学编辑、选区、结构退出顺序 |
| `enter.rs` | Enter、Shift+Enter；已有处理器 | 命令候选、Align 换行、数学退出/拒绝、正文换段或软换行 |
| `tab.rs` | Tab；已有处理器 | 命令补全、数学上下文保留焦点、正文空格 |
| `backslash.rs` | `\` 命令前缀；待迁移 | 开始命令模式；保持现有命令输入语义 |
| `dollar.rs` | `$`；071 新增目标，尚未实现 | 进入数学模式；按语义字符命名，物理键位由 Qt 按当前键盘布局映射。`、`、`¥` 和 `￥` 保持普通文本，不作为快捷键 |
| `backspace.rs` | Backspace；071 待迁移 | 正文删除、命令输入删除、公式内部删除和边界行为 |
| `mod_backspace.rs` | Mod+Backspace；已存在，纳入统一规则 | IME/命令行、数学编辑、行内环境、块环境顺序 |
| `delete.rs` | Delete；表格目标，延后接入 | 前向删除及结构/表格上下文行为；表格节点按 045/046 接入后实现 |
| `left_arrow.rs` / `right_arrow.rs` | Left / Right 与 Shift 变体；071 待迁移 | 命令行光标、数学内部移动、正文视觉候选、公式宿主进入和边界行为；修饰变体随对应实体键管理 |
| `up_arrow.rs` / `down_arrow.rs` | Up / Down 与 Shift 变体；071 待迁移 | 命令行候选选择、公式内部移动、正文 preferred x 候选；修饰变体随对应实体键管理 |
| `home.rs` / `end.rs` | Home / End 与 Shift 变体；071 待迁移 | 命令行行边界、公式文本行边界、正文视觉行边界；修饰变体随对应实体键管理 |
| `page_up.rs` / `page_down.rs` | PageUp / PageDown；后续结构任务 | 同类结构导航，按对应结构任务接入时再实现 |
| `space.rs` | Space 与修饰变体；071 纳入现有映射 | 命令查询空格、逐级扩大结构选区及其他上下文规则 |
| `alt_t.rs` | Alt+T；未实现，快捷键表中的表格规划 | 插入表格；仅在 045/046 接入后实现 |
| `mod_c.rs` / `mod_v.rs` | Mod+C / Mod+V；已支持但当前在 Qt/app | 复制/粘贴的会话语义与作用域；系统剪贴板读写由 app 适配层提供 |
| `mod_z.rs` | Mod+Z / Mod+Shift+Z；当前由窗口 Shortcut 发起 | 画布焦点下的 Undo/Redo Session 优先级、公式源码草稿本地历史与文档历史 |

071 验收范围是当前已支持的画布编辑器快捷键；逐项对照[唯一键位清单](keyboard-shortcuts.md)核全并迁入，不得漏项。表格等尚未实现的规划键只记录目标文件和依赖，功能本身留在 045/046 等后续任务。未来新增编辑器快捷键也按具体快捷键或独立语义家族加入同一目录，不在 app、QML 或领域模块另建仲裁入口。按键模块接受 app 从同代布局快照算出的单次候选位置、视觉 affinity 或 preferred x 等必要标量，并负责上下文裁决、Session 状态校验和提交；app 保有并计算页面布局模型和视觉几何，engine 不复制或重算这些数据。候选无效时必须在任何焦点/文档迁移前拒绝，保证失败原子性。

只改变扩选/修饰状态的变体（如 Shift+方向键）随基础键处理；形成独立语义动作的修饰快捷键（如 Mod+Backspace、Mod+Z）可有独立文件，仍由单一 Session 键盘入口分派。Qt 负责物理键和平台修饰映射；IME 预编辑仍由 Qt 输入适配先处理。

### 当前基线行为

下表记录本次架构决策前已存在的行为和分派例外，供迁移时保持兼容；它不是理想化的统一路由现状。

| 按键 | 当前行为与例外 |
| --- | --- |
| Escape | 数学编辑分派可先取消数学文本 composition，或恢复/退出数学源码草稿和公式焦点；否则命令输入先取消，之后处理 composition、块环境选择或普通选区，最后尝试退出结构。普通选区 Escape 只收起选区，再按一次才退出结构。 |
| Enter / Shift+Enter | 命令输入下 Enter 接受候选、Shift+Enter 无操作；公式 Align 中 Enter 插入行分隔，数学文本分支拒绝换行，其他公式 Enter 退出；正文分别插入段落或软换行。 |
| Tab | 命令输入交给 `TabCommandLine`：字体候选确认、普通查询补全、空查询退出并插入字面 `\`；公式中保留公式焦点；普通正文插入两个字符宽空格。表格 Tab 导航尚未实现。 |
| Mod+Backspace | composition/命令输入中不改正文；数学编辑按公式规则处理；正文优先解除可解除的最内层行内环境，否则尝试解除块环境并保留内容。 |
| Left / Right / Up / Down / Home / End | Qt `m_command_mode` 会先处理部分按键；其余事件经 app 导航入口取得布局几何。MathText 有专门视觉移动，MathTree 的水平移动走数学命令；MathSource 与部分数学树导航尚有缺口。当前生产画布导航没有调用 `Command::EnterMath`，issue 所述公式进入路径未接通。 |
| Mod+C / Mod+V | Qt 直接发出剪贴板请求，app 读取或写入系统剪贴板，再调用编辑接口；当前未由 Session 按键仲裁器决定命令行/公式/结构选区中的复制粘贴语义。 |
| Mod+Z / Mod+Shift+Z | 窗口 `Shortcut` 调用 app undo/redo；Session 负责文档历史，公式源码草稿有自己的 undo/redo 优先级。键位尚未进入逐键 Session handler。 |
| 结构与表格修饰键 | Qt 识别结构导航并发出独立意图；结构移动和扩大结构选区已有入口。表格快捷键尚属 045/046 规划，表格节点接入前不启用；实现时仍须按对应实体键纳入逐键处理。 |

上述基线把当前行为与迁移目标分开记录。完成迁移后，保留可观察行为和各上下文的既有差异；对未实现的键只建立经过设计的优先级，不把键位清单中的未来目标写成已支持行为。

## 状态与优先级

导航键的目标处理顺序（设计规则；具体优先级按键可有差别）如下：

| 顺序 | 目标 | 说明 |
| --- | --- | --- |
| 1 | 命令输入 | 光标键移动命令行光标，不移动正文 |
| 2 | IME composition | 导航不改正文选择；IME 提交、取消仍由 composition 协议处理 |
| 3 | 结构选区 | 结构选择拥有当前编辑焦点 |
| 4 | 数学树 / 数学文本 / 数学源码 | 由公式编辑分支决定内部导航语义 |
| 5 | 块环境退出停靠点 | 后续边界键处理已有的环境退出状态 |
| 6 | 正文 | 从布局快照取得视觉候选，再提交 Rust 选择变化 |

每个按键文件可以有不同的状态优先级，不应把导航顺序机械套到 Enter、Tab 等按键上。交互字段也不是一概互斥：已确认 MathEdit 可与 MathText composition 共存，也可与 command line 共存；其他组合要逐项确认允许/拒绝条件，不推断为任意组合均合法。每次路由只选择拥有本次按键的处理者，并保留其他合法状态。

方向键的视觉顺序、双向文本亲和性和 preferred x 属于布局几何信息；Session 不应复制 Parley 页面模型。Session 负责判断导航目标、允许/拒绝迁移和提交选择/结构变更。app 负责把同代快照上的几何候选交给 Session，并投影结果。公式内部树路径、文本岛和源码位置由数学领域模块负责。

## 当前一致性审查

目前不能说所有快捷键设置和处理架构完全一致，存在有意分层和待收敛的旧边界：

- 当前基线中，`EditorKey` / `Session::run` 仅覆盖部分语义按键；`keyboards/` 已有 Escape、Enter、Tab 与 Mod+Backspace 文件。方向键、Home/End 仍经 `DocumentViewRuntime` 的独立入口，公式按键规则也部分分布在 `math_edit.rs`；issue 描述的生产路径并未调用 `Command::EnterMath`，所以画布视觉方向键尚不能据此认为能进入公式。071 要将现有编辑器按键逐项迁入实体键模块。
- 当前 app 计算水平、垂直和行边界导航几何，并承担块环境虚拟停靠点及部分环境退出判断。目标是让逐键 Session 处理器接收几何候选并裁决语义；布局几何仍归 app。
- Qt `keyboard.cpp` 中 `m_command_mode` 仍会前置处理部分 Backspace/方向键，与“所有正文语义先交 Session”的目标并不完全一致。IME 预编辑期间的 Qt 消费是输入法适配例外，不应误当领域焦点副本。
- `editing.rs` 会预测 Enter/Tab 的文档副作用，字体选择器也有特殊路径；应逐步改为把意图交给 Session，避免 app 再维护 Rust 状态的预测副本。
- 结构导航有专用入口；MathTree 垂直和行首/行尾行为尚未实现。未支持的意图应保持当前公式焦点，不应落回正文修改选择。

因此当前答案是：不同作用域有职责边界，但当前编辑器内的快捷键分派不一致。task 071 负责统一现有画布快捷键的逐键管理，同时保留窗口、控件和平台输入适配的边界。

## 新增与修改快捷键的规则

1. 在[快捷键表](keyboard-shortcuts.md)写明平台键序列、焦点作用域、用户动作和冲突行为。
2. 先确定最内层焦点所有者；弹窗、命令输入、IME、结构选择和公式编辑不得由更外层处理器抢先改写文档。
3. 纯窗口动作放窗口快捷键；控件本地动作留在控件；画布物理键映射集中在 Qt 键盘入口；编辑状态相关语义交给 Session 命令/意图路由。
4. 视觉导航把同代布局几何作为候选数据传入，Session 不重算像素几何；Session 不因单次路由目标而强制合并可并存的持久状态。
5. 为键位映射和领域行为分别添加测试，覆盖焦点作用域、优先级冲突、事件消费、状态不变性及文档副作用。
6. 不为静态快捷键表增加运行时注册表。只有用户重映射或动态扩展成为需求时，才建立含稳定动作 ID、平台键序列、作用域、冲突优先级与可用条件的描述符；动作仍委托给已有命令入口。
