# 文档格式导入与导出

更新日期：2026-10-29。

## 规范模型与适配边界

`caret-doc` 的版本化文档树是 Caret 唯一的规范 AST，`.cdoc` 是其原生持久化格式。不要再设计一个缺少格式语义的通用 AST，作为 `.docx`、`.tex`、`.md` 和 Caret 之间的中转模型；这会形成第二套长期数据模型，并迫使各格式都退化到共同子集。

每种外部格式有独立的读写适配器。导入器将格式解析为该格式能表达的结构，再映射到规范文档树；实现复杂格式时可以在适配器内部建立短生命周期的源格式 IR，用于包关系、样式继承、宏/环境等映射，但 IR 不跨格式共享、不写进 `.cdoc`，也不替代规范模型。简单格式可以边解析边构造文档树。导出器从规范文档树生成目标格式自己的结构。

```text
.docx / .tex / .md
        │
        ├── 格式专属解析器 / 可选的短生命周期源 IR
        │
        ▼
Caret 规范文档树（caret-doc） ──► .cdoc
        │
        └── 格式专属导出器 ──► .docx / .tex / .md
```

转换边界返回结构化诊断：源位置、映射出的文档位置（若可得）、不支持的结构、发生的简化及建议操作。不得静默丢弃内容或格式。导入在临时文档中完成解析和验证并展示转换摘要后，才允许安装为新文档会话。若当前会话为 Edited，先复用 018 定义的 Save / Don't Save / Cancel 关闭确认；用户取消、保存取消或保存失败时保留当前会话。导入请求携带会话 generation，迟到结果不得覆盖已切换或更新的会话。导出只写目标文件，不改变原 `.cdoc` 的路径、标题或保存状态。

## 保真与失败规则

- 导入保留可映射的结构与语义；只有源格式独有、Caret 模型无法表达的内容才进入降级报告。
- 导出必须将每一种 Caret 支持的节点和媒体通过目标格式原生结构或版本化 Caret 扩展完整编码；不能以“用户确认降级”替代完整内容支持。用户确认降级只适用于源文件独有且 Caret 无法表达的外来功能。
- Caret 扩展与面向第三方编辑器的可读回退内容必须通过扩展版本、稳定节点映射和回退内容摘要绑定。重新导入时验证摘要；外部编辑器改动了回退内容而扩展仍保留时，报告冲突并要求明确处理，不得静默用旧扩展覆盖改动。扩展缺失或损坏也必须可见报告。
- 对无法安全映射或可能改变内容含义的构造，拒绝导入并保留源文件；不得把未知结构伪装成普通文本后宣称无损。
- 导出默认完整模式必须保留所有 Caret 内容；格式独有的源结构无法表示时，可报告并拒绝。若未来提供面向第三方兼容的降级导出，必须作为单独、明确选择的便携模式，不能取代完整模式。导出不改写当前文档。
- 首版不承诺与源应用逐像素、逐页一致，也不承诺外部格式往返逐字节相同；只对文档结构与明确支持的语义定义往返契约。
- 文件读写需限制解压后大小、嵌套深度、节点数和资源数量；从文件导入不执行代码、宏、脚本或外部链接。

## 格式范围

### `.md`

采用明确命名的 `Caret Markdown v1` 方言：CommonMark 0.30、GFM 表格和 Caret 数学扩展。完整覆盖 Caret 文档模型中的段落、标题、环境、强调、代码、任意受限深度的嵌套/多段列表、引用、链接、行内图片、硬/软换行、表格、公式、媒体资源和文档设置。使用 Markdown 原生语法能表达的内容写成标准结构；Caret 专有语义用带版本、节点映射和回退摘要的 Caret Markdown 扩展保存，保证 Caret 往返完整。其他 CommonMark/GFM 应用可忽略扩展并显示普通 Markdown 回退内容；回退内容被编辑后重新导入时必须检测并报告扩展冲突。代码是惰性文本，不执行；外部图片只读取受限的本地相对资源，绝不下载远端 URL。硬换行映射为显式行内断行；软换行按段落空白语义处理。原始 HTML、未知扩展、图片引用无法解析或损坏源内容必须诊断/拒绝，不得静默丢弃。导入导出不得在任何 Caret 文档节点或媒体能力未完成前开工，具体依赖见 047。

### `.tex`

TeX 导入导出必须完整覆盖 Caret 文档节点和媒体；用标准 LaTeX 结构表达通用内容，Caret 专有语义由带版本、节点映射和内容摘要的无执行副作用的 Caret TeX 结构保存。若 TeX 作者修改了回退内容而保留扩展，重新导入必须报告冲突，不得静默覆盖。导入不运行任意宏、shell escape、外部程序或用户包；只解析明确支持的语法，不能执行宏来恢复结构。只读取受支持的本地/包内图片资源，不展开任意文件路径。`latex-rust` 用于数学表达式/数学盒，不是完整 LaTeX 文档解析器；章节、段落、列表、表格、图片和完整往返由独立适配器处理。输入中无法解释的外部 TeX 功能产生转换报告或拒绝，不得伪称完整导入。

### `.docx`

`.docx` 是包含多个部件及关系的 Open XML 包，不是单个扁平 XML 文档。导入器需按包关系读取部件，将所有 Caret 内容映射为 WordprocessingML 原生结构；对于 OOXML 无原生等价的 Caret 节点，使用带版本、节点映射和回退内容摘要的 Caret 自定义 XML 部件和可读回退呈现，保证 Caret 往返不丢失。重新导入时检测回退内容是否被外部编辑器改动；发现扩展与可见内容不一致时报告冲突，不静默覆盖。DOCX 导入导出等待 047 及其前置的所有文档节点、媒体、表格、公式、排版和画布能力完成。外部关系不得自动访问。源文件中 Caret 无法表达的修订、批注、嵌入对象等必须报告或拒绝，不得静默丢弃。

## 后续任务

格式适配按边界分任务：先完成全部文档语义与可见呈现，再执行格式转换。047–049 都只能在完整 Caret 文档模型、媒体、图片/表格/公式布局、排版与画布能力验收后开始；047 先完成 Markdown 转换服务与完整模型往返，048/049 再分别覆盖 DOCX/TeX。每种格式都必须为 Caret 支持的所有内容提供可往返表示；源格式独有、Caret 无法表达的内容提供结构化损失报告并由用户确认或拒绝。各适配器共用规范 AST 与导入导出服务生命周期，不共用源格式 AST。
