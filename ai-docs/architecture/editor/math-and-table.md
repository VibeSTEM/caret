# 公式与表格

更新日期：2026-11-01。

## 公式节点和 LaTeX 语义

公式是可编辑的语义树，不是普通正文中的 LaTeX 源码。Caret 持有稳定、版本化的文档节点、占位符和 `MathPos`；解析器直接产出这棵树，没有中间 AST。公式布局从同一数学树产生绘制、命中测试与光标几何。

首版采用 LaTeX 对应名称：

| Caret 节点 | LaTeX 术语 / 写法 | 位置与语义 |
| --- | --- | --- |
| `InlineMath` | inline math：`$...$`、`\(...\)` | 段落内的行内对象，内部位置用 `MathPos` |
| `Equation` | `equation*` / `\[...\]` / `$$...$$` | 独占一行的无编号显示公式块；不是可自动折成普通段落的文本行 |
| `Align` | `align*` | 多行无编号显示公式；每行有对齐单元格，`&` 是对齐点，`\\` 是公式行分隔 |

命令面板中的可读别名与公式源码分隔符是两套输入语法，不混用：`\math` 创建行内公式，`\equation` 创建单行显示公式，`\align` 创建多行对齐公式。`$...$`、`\(...\)`、`\[...\]` 等是公式源码导入语法，不作为命令候选；候选表达插入的结构，而不是源码边界标点。

首版只支持无编号的显示公式：不实现自动编号、`\label`、`\ref`；编号版 `equation` / `align` 不得静默丢弃编号语义，首版应明确报不支持并保留输入。公式源文本可保留用于错误位置和导出；解析或规范化后不保证与原始 LaTeX 字符串相同。未支持的命令必须报错并保留原内容。正文 Shift+Enter 的 `SoftBreak` 与 `Align` 行分隔是不同结构。

### 正文结构示意

下面的 JSON 展示公式节点在文档正文中的位置：行内公式属于段落的 `inlines`，显示公式和多行公式是正文块。字段与校验规则见 [043 模型与编辑](../../task/043-math-model-and-editing.md)。Caret 数学树保留 TeX 原子与符号顺序，不解析成代数关系或运算语义。

```json
{
  "body": [
    {
      "kind": "Paragraph",
      "inlines": [
        { "kind": "Run", "text": "质能关系：" },
        { "kind": "InlineMath", "mathTree": "<compact math tree>" }
      ]
    },
    { "kind": "Equation", "mathTree": "<compact math tree>" },
    {
      "kind": "Align",
      "rows": [
        { "cells": ["<compact math tree>", "<compact math tree>"] },
        { "cells": ["<compact math tree>", "<compact math tree>"] }
      ]
    }
  ]
}
```

`<compact math tree>` 是说明性占位符，代表 `MathTree { schemaVersion, source, root, extra }`：`source` 是与当前树对应的 LaTeX，`root` 是有序 `MathNode` 树，`extra` 保留未知字段。

### 数学树的规模约束

每个节点只保存自身的原子文本和有序子节点；单棵树受深度 32、节点 65 536、可变载荷 8 MiB 与源码 1 MiB 的上限约束。行内公式在段落逻辑文本中占一个 U+FFFC（3 字节），作为原子对象参与编辑和布局。若测量显示大量公式文档的内存或编辑成本成为热点，再评估连续 arena 等紧凑表示，不改变 `.cdoc` 编码。

## 解析、数学排版和字体

公式后端是工作区内的 `caret-math` crate，选型依据见[研究 010](../../research/010-typst-math-layout.md)：

- 解析：自写 LaTeX 数学子集解析器直接产出 `caret-doc` 的 `MathTree` / `Align`；序列化器把树写回 LaTeX，`parse(serialize(tree))` 与原树结构一致。
- 排版：`layout/` 移植自 Typst v0.15.1 的数学排版（分式、根式、上下标、定界符、重音、矩阵与对齐、原子间距），度量全部来自 OpenType MATH 表，经 `read-fonts` / `skrifa` 读取。移植文件的来源与修改记录在文件头，见[源码署名](../../standards/source-attribution.md)。
- 输出：`MathLayout` 只含字形 ID、位置、实心矩形、宽度与上下伸，直接写入页面字形快照；绘制、命中和光标共用这份几何。SVG/PNG 不是文档模型，也不是交互路径。
- 缓存：`MathLayoutEngine` 驻留在布局服务中，按公式内容、字号、样式与字体缓存排版结果。

LaTeX 没有唯一公式字体。M3 首版内置 STIX Two Math（OFL），三平台不依赖本机字体。文档保留 `defaultMathFontFamily` 作为扩展入口；未设置时使用 STIX Two Math，其他值原样保留。未来扩大支持列表时，应另行处理字体度量、缺字回退、缓存与 `.cdoc` 重现性。

公式中的 `\text{...}` 当前用数学字体的正体字形排版；交给 Caret 正文 shaping（含文档语言与字体回退）由 044 继续实现。缺字时绘制占位方框并产生诊断，不静默丢弃内容。

解析输入和手建树都受明确上限约束（深度、长度、节点数）；超限返回错误而不崩溃，也不破坏现有公式源内容。

## 导航和编辑

- `\math` 插入行内公式，`\equation` 插入单行显示公式，`\align` 插入多行对齐公式；三者均进入公式编辑。`$...$`、`\(...\)`、`\[...\]` 是公式源码解析/导入语法，不是正文命令入口。
- 结构命令可显式插入 `Align`；LaTeX 无编号 `align*` 的 `&` 与 `\\` 映射为对齐点与行节点。
- 公式编辑状态 `MathEdit` 记录目标公式、LaTeX 源码与源码字节偏移。每次修改重新解析源码并写回公式树；解析失败拒绝修改，文档不变。插入点几何由公式排版树上对应节点的边缘给出。
- 左右键按停靠点移动：花括号组内、token 边界；控制词整体跳过与删除。到达边界再按一次离开公式；正文中折叠光标紧邻行内公式或位于显示公式相邻段落边缘时，左右键进入公式。Esc 与 Enter 离开公式；行内公式落到公式前后，显示公式落到相邻段落。上下键、鼠标与其他选区命令也离开公式。
- `_` 与 `^` 插入带空组的下标与上标，`{` 自动补 `}`，`}` 跳出组。
- 公式编辑中 `\` 打开公式子命令（分数、根号、上下标、希腊字母等），不打开正文命令。`Align` 中 Enter 插入 `\\` 结束一行，`&` 为对齐点。
- 空公式中退格删除整个公式对象。

离开公式只移动插入点，不产生撤销步。改树的命令才记账。

## 表格

表格是块。单元格里是普通的块序列，所以单元格里可以有多段，也可以再放公式。第一版不允许单元格合并。

- 表格单元格导航的目标行为：Tab 到下一格，最后一格再按 Tab 增加一行；Shift+Tab 到上一格。该行为尚未接入当前 `EditorKey::Tab` 路由；实现时由 Rust 先处理表格上下文，再回退到正文空格行为。
- 单元格里按 Enter 是新起一段，不是在表外插入行。
- 方向上的结构键在单元格之间移动，到边缘再离开表格。
- 插入默认 2×2。增删行列是独立命令。

大表格只重排 `layoutRev` 变了的单元格内容。整表重排的开销在 M4 用一份宽表测量，测量前不设毫秒门禁。
