# Block 宿主共享交互协议

更新日期：2026-11-11。本文定义 Paragraph 与其他 Block 共用的位置、移动、选区、删除和历史交互协议。持久化类型与容器关系以[文档树与结构](document-structure.md)为准；位置坐标以[文档位置](document-position.md)为准；导航和几何投影以[结构导航](../structure-navigation.md)为准；行内环境视图以[环境视图](environment-views.md)为准。

## 类型与职责

`Block` 是文档模型的块级类别，`Paragraph` 是其中结构最简单、现有编辑规则最完整的一种 Block。Section、Equation、Align 等块有更复杂的内容结构。Inline 内容处在 Paragraph 内，或处在其他 Block 明确暴露的行内流内部；Inline 不是块序列中的第三类外层节点。

Paragraph 是共用交互行为的基线，不是可直接替代所有位置类型的通用实现。先以 Paragraph 中已验证的位置、顺序、移动、选区、删除、历史和失败行为作为回归基准，抽取可共享的不变量；复杂 Block 通过适配器接入，不把 paragraph_id/UTF-8 坐标强制用作其位置表示。通用层不可迫使 Paragraph 携带 Section/Equation 专属的虚拟停靠状态、块背景或内部容器状态。

Session 的共享底座拥有跨宿主交互权威；适配器只映射宿主数据。统一指共享位置解析、顺序、范围和状态转移的契约，不强迫各宿主使用同一坐标，也不要求把当前 Session 中数学编辑分支、PendingInlineStyle、视觉 affinity、组合输入和历史恢复等不同语义机械合并成一个字段。相同逻辑焦点或选区不得被多个模块各自作为权威维护；必要的编辑上下文仍由其明确的领域状态拥有。

位置类型的语义和全树排序约束见[文档位置](document-position.md#跨宿主位置与顺序)。位置及选区的具体 Rust 类型属于实现细节；索引、只读位置解析和经验证的可变事务定位可由各自职责模块承载，但必须使用一致的身份、父链、顺序与文档代际校验。

| 责任 | 共享底座 | 宿主适配器 |
| --- | --- | --- |
| 稳定身份与顺序 | 解析并比较统一宿主范围 | 提供 Block ID、父级路径和同级顺序 |
| 焦点与移动 | 提交移动/扩选状态转换，校验位置有效性 | Paragraph 提供 TextMap/TextFlow 候选；复杂 Block 提供内部位置及边界候选 |
| 选区 | 保存 anchor/focus 方向，构造跨宿主范围，协调高亮与编辑目标 | 将宿主内部坐标映射为其文档范围和几何 |
| 删除与替换 | 选择目标范围、生成原子操作、维护 Undo/Redo 和失败原子性 | 通过领域事务删除/替换本宿主内容并返回位置映射 |
| 视觉反馈 | 保证位置、选区、命中和高亮使用同代快照 | 提供 caret、选区矩形及可选的宿主背景几何 |

适配器不能重复持有权威焦点、边界退出、文档顺序、选区或历史状态，也不能为同一快捷键再做一套上下文仲裁。键位优先级由[快捷键管理架构](../../interface/keyboard-shortcut-architecture.md)维护；快捷键 handler 把输入意图交给共享宿主协议。

## 适配能力

宿主位置类型和位置映射以[文档位置](document-position.md)为准；键盘转换和几何候选以[结构导航](../structure-navigation.md)为准。共享协议消费适配器提供的合法宿主位置，统一处理文档顺序比较、扩选和删除事务；它不要求不同 Block 采用同一坐标表示，也不把视觉能力塞进位置类型。

Block 适配器只声明领域需要的内部位置、边界候选和内容事务。Section 提供标题/子块位置；Equation 提供公式内部位置；Align 还提供行/cell 位置。它们不在本地重复实现导航、选区或删除仲裁。

视觉背景是独立可选能力，不是每种 Block 都必须有的部分。Paragraph 通常没有块级活动背景；需要环境背景的 Section/Equation/Align 才提供对应几何。无视觉背景是有效结果，不改变焦点或选区语义；绘制规则以[画布与交互背景](../../interface/canvas-highlighting.md)为准。

## 一次宿主交互

```text
键盘 / 鼠标意图
    → Session 解析当前有效位置及宿主顺序
    → 共享协议计算目标位置、anchor/focus 或删除范围
    → 宿主适配器执行内容事务并返回位置映射
    → Session 原子提交焦点、选区、历史和 generation
    → 同代布局快照提供 caret / 选区 / 可选背景几何
```

如果位置、宿主路径或事务映射无法安全解析，操作必须在写文档前拒绝，并保留文档、焦点、选区、generation 和历史。禁止用“最近 Paragraph”作为所有 Block 失败时的兜底；最近的有效宿主边界可能是相邻 Block。

## 跨 Block 结构选区与历史

Shift+方向键使用相同的位置比较和范围构造，不单独绕过共享模型。数学内部选区先按 MathTree/MathText 的语义扩展；越过宿主边界时将数学对象作为稳定结构范围纳入文档选区。删除、替换、复制消费相同的已选范围，不得出现可视选中但文档范围为空、删除后只剩隐藏选择，或复制丢失所选数学对象的情况。

### 范围端点与对象纳入

文档级结构选区的 anchor/focus 各是一个可解析文档位置：段落或环境标题中的文本位置，或者在范围边界落在复杂 Block 对象边界时的块外侧边界。块外侧边界保留 Block 稳定 ID 与侧向，不在安装范围时改写成相邻段落位置；落点、命中与几何投影再把它规范到该侧最近的文本位置。两个端点的规范间隙相同但操作目标不同的情况仍不合并。端点必须能在同一 Session 与 document generation 内比较，不能只按裸偏移或节点 ID 排序。

结构范围按文档顺序纳入完整覆盖的复杂 Block：范围起点不晚于 Block 外前、终点不早于外后时，该 Block 作为整体进入范围。Section/Custom 以整棵环境子树为一个对象；扩选从环境内部越到其外前/外后边界时，把范围另一端扩展到该环境的相对边界，使环境整体进入范围，与鼠标跨越块环境边界的选择一致。Equation/Align 以原子对象进入范围，对象内部的 MathTree 随对象一起删除、恢复与复制。InlineMath 与 InlineEnvironment 仍由段落文本范围中的 U+FFFC 或字符偏移表达，不另立对象端点。

扩选在公式宿主内部时按 MathTree/MathText 的局部 anchor/cursor 语义移动；到达宿主边界后转换为覆盖整个公式对象的结构范围，并把 caret 停靠到同侧外侧边界。源码分支当前没有本地选区，扩选不伪造文本范围。结构范围删除后 caret 折叠到范围起点一侧最近的有效边界；端点段落随对象删除时按文档顺序退到最近的幸存段落，最后才创建补位空段落。块环境的单值选择从多选列表派生，不单独维护第二份权威状态。

删除结构选区时，只移除选中的 Block 与文本范围；范围中间的普通段落保留各自边界，只截断两端文字，不把被跨越的段落合并成一段（普通纯文本跨段删除仍合并段落）。焦点折叠到删除范围附近最近的有效宿主边界，可以落在 Paragraph 或相邻 Block。若文档不剩可编辑内容，再创建一个空 Paragraph 供继续输入。Undo 恢复删除前有效的普通插入位置与视觉 affinity，但不恢复结构高亮；Redo 恢复删除后的折叠位置。没有可撤销操作时，Undo 不改变结构选区；撤销/重做后清除不再对应当前文档的虚拟块外侧状态。

本契约用于文档级结构选区的删除/替换。光标处直接删除单个公式对象的 MathEdit 目标和焦点恢复由[数学公式](../math.md)维护；Section/Custom 的标题、子树和解除目标由[块环境模型](document-environments.md)维护。

## 扩展约束

| Block 形态 | 内部适配职责 | 共用协议职责 |
| --- | --- | --- |
| Paragraph | TextMap/TextFlow、段落样式与文本事务 | 焦点顺序、跨宿主选区、删除/替换、历史和失败状态 |
| Section/Custom | 标题、子块顺序、解除/删除语义与容器几何 | 块相邻、跨宿主导航、结构选区、事务和恢复 |
| Equation | MathTree/MathText 位置与 MathFragment 几何 | 块顺序、边界转换、跨块选区和删除恢复 |
| Align | MathTree、逻辑行/cell 路径和 Align 几何 | 块顺序、宿主范围、历史与跨块选区 |
| Table/Figure（未来） | 单元格、图形锚点或领域内容位置 | Block 身份、文档顺序、焦点/选区/删除/历史共用协议 |

Table、Figure 是未来 Block 扩展例子；本表不代表节点或编辑能力已经实现。新增 Block 必须沿该协议接入，不复制 Paragraph 或其他 Block 的交互仲裁。

## 实现承载

共享交互首先属于 `caret-engine` 的 Session 编排职责：它协调现有文档、结构、布局输入和事务，不拥有独立于编辑会话的领域数据。优先在 `editing/session/` 内建立单一职责模块并按仓库模块规范拆分；不为移动代码或缩短文件创建 crate。只有将来出现稳定、独立复用且不依赖 Session 编排的能力时，才重新评估 crate 边界。

本文、[文档位置](document-position.md)和[结构导航](../structure-navigation.md)共同定义长期交互规则；实现细节不得改变这些可观察契约。
