# 057 — 块环境命令作用于文本选区

## 目标与背景

当前结构命令能创建块环境，但尚未定义在已有文本选区上执行块环境命令的行为。用户期望可以选中文本后通过命令创建块环境。块环境包含独立结构（例如 Section 标题与正文），不能直接套用行内环境包裹规则。

## 范围与非目标

定义并实现对非空文本选区执行块环境类命令的行为，以 `\section` 为首个可观察样例。设计应供后续可选择的块环境复用：环境/命令注册信息声明选区适用性，按环境语义定义内容映射，通用事务负责范围替换、位置映射和 Undo；不得让 Qt/QML 为每个环境复制一套包装逻辑。保留既有无选区命令行为。范围包括选区是否合法、文本在环境标题与正文间的归属、跨段选择、已有块环境内外的约束、命令后的光标/选区位置、失败原子性、Undo 与位置映射。

本任务不实现行内 `\bold`、`\italic`、`\font` 的选区格式化；这些由 025 负责。也不增加环境工具按钮、任意宏或脚本执行能力。

## 前置条件与待决策

实现前须根据当前 Section 模型确定所选文本和完整段落的转换规则，特别是部分段落选择、跨段选择及 Section 独立标题如何保留选中内容；规则需先写成可观察行为和黑盒用例，再实现。不能在命令执行时丢弃或静默改写未选正文。

## 实施步骤

1. 审核现有块环境命令、选区模型、块容器操作与位置映射，识别可复用的稳定领域接口。
2. 明确选区转换契约，覆盖完整段落、部分段落、跨段和已有环境边界。
3. 在 Rust Session 中以单一事务实现环境创建，保持文本、节点 ID、选区方向及失败原子性。
4. 接入命令可用性与失败反馈；Qt/QML 只传递选区和命令意图。
5. 添加命令级黑盒测试，覆盖成功、非法范围、撤销/重做和位置映射，并完成独立评审。

## 预计改动

`crates/caret-engine/src/editing/session/` 中的结构环境命令与事务测试；必要时更新 `caret-structure` 的稳定范围查询。只有在单一职责确实膨胀时才拆新文件；不新增 crate。

## 验收标准

- [ ] `\section` 能对支持的非空文本选区创建 Section，所有选中内容按定稿契约保留在正确标题/正文位置。
- [ ] 选区适用性和内容映射按块环境语义声明，新增可选择的块环境不需要复制 Qt/QML 逻辑或另建一套通用选区事务。
- [ ] 部分段落、跨段、选区方向、嵌套环境及不合法边界行为明确且有行为测试。
- [ ] 操作产生一个原子撤销步骤；撤销/重做恢复文档树、稳定 ID 和选区位置。
- [ ] 命令失败不改变正文、选区、结构索引或撤销历史。
- [ ] Qt/QML 不构造 Section 树或重复实现领域规则；状态和错误从 Rust 结果投影。
- [ ] 独立评审与受影响验证通过。

## 风险与回退

Section 标题与正文分离，部分段落选区直接包裹会改变原段落语义。若选择映射规则无法保持内容和光标位置，应拒绝该范围，不得静默降级为普通 Section 创建。
