## 目标与背景

实现 `.docx` 所有 Caret 内容的导入导出。必须等待 047 所依赖的全部文档模型、资源、排版和画布能力完成；不分阶段先做文本子集。DOCX 是包含多个部件及关系的 Open XML 包，不能按单个正文 XML 或扁平通用 AST 处理。架构边界见[文档格式导入与导出](../architecture/editor/document-interchange.md)。

## 范围与非目标

- 通过包关系发现并解析 OOXML 部件；Caret 文档模型中的每种节点和媒体都必须有 WordprocessingML 表示，或有版本化的 Caret 自定义 XML 扩展及可读回退。
- 建立 Caret 完整内容的 DOCX 导入/导出矩阵与端到端往返样例。
- 导出生成结构有效的 `.docx` 包，并保证写入原子性。
- 不要求导入 DOCX 所有 OOXML 特有功能；Caret 无法表达的修订、批注、嵌入对象等须进入转换报告，并在用户确认降级后才继续。不运行宏或自动访问外部关系。
- 不在本任务设计或实现另一份通用交换 AST。

## 前置条件与待决策

- 010、012、021、025 已提供目标结构、表格、持久化和格式语义。
- 实施前独立审查可用 Rust OOXML/ZIP/XML 库、许可证、维护状态和安全限制；不因格式复杂就直接自研完整 OOXML 栈。
- 明确映射到 Caret 的 OOXML 输入子集、Caret 扩展表示及样例来源/许可。

## 实施步骤

1. 评估并记录依赖库，构建安全的包读取和关系解析边界。
2. 用源格式局部 IR 或流式解析将支持的 OOXML 结构映射到 Caret 树。
3. 实现 OOXML 输出器、原子写入和可定位的转换报告。
4. 以行为测试验证结构映射、样式/编号语义、未知构造与失败副作用；独立评审后补记录。

## 预计改动

新增 DOCX 格式适配器、必要的依赖与真实样例测试；规范 AST 仍由 `caret-doc` 管理，包级机制不得泄漏到 Qt/QML。

## 验收标准

- [ ] 所有 Caret 文档节点和媒体资源均能通过 OOXML 原生结构或 Caret 扩展完整导出，并从自身扩展完整重开。
- [ ] Caret 扩展和 WordprocessingML 可读回退的一致性可校验；外部编辑后冲突有报告和显式处理路径。
- [ ] 外部 OOXML 输入中不属于 Caret 模型的功能均能定位并报告，不会静默抹除。
- [ ] 未支持的部件和结构有报告；不会静默丢弃后宣称无损。
- [ ] 包大小、解压大小、关系解析、嵌套和资源数量受到限制；不访问外链或执行活动内容。
- [ ] 导入失败不替换当前会话；导出失败不留下半成品文件。
- [ ] 测试基于可观察结构、文件副作用和诊断。
- [ ] 依赖审计、独立评审和验证结果均已记录。
