## 目标与背景

在 044 完成数学布局、快照与基础命中/光标后，继续验收多行公式的方向键、选择和鼠标拖动体验，以及复杂双向文本在数学文本岛中的交互。该任务补齐 011 的端到端交互验收，不重复实现 043 的模型事务或 044 的布局算法。

## 必读

- [数学公式](../architecture/editor/math.md)、[044 公式布局与画布](044-math-layout-and-rendering.md)、[011 数学公式总验收](011-impl-math.md)
- [验证与评审](../standards/validation-and-review.md)、[测试规范](../standards/testing.md)、[页面画布与命中测试](027-canvas-and-hit-testing.md)

## 范围与非目标

- 验收并修正数学文本的复杂 bidi caret、选择和 hit mapping；检查 mixed RTL/LTR、标点、嵌套粗斜体与空文本岛。
- 验收鼠标拖选跨 InlineMath、Equation、Align 单元格及普通正文边界的路径、焦点迁移与失败原子性。
- 验收 Align 行/单元格间上下导航、目标 x 保留、短行与空 cell 行为；检查 Shift 扩展选择和跨 TextFlow 禁止边界。
- 在 macOS、Windows、Linux 可用桌面环境执行代表性公式输入、命中、选择和编辑验证；没有可用窗口的 runner 不能代替真实桌面证据。
- 不修改通用正文选择算法，除非行为差异经回归证明属于共享核心缺陷；不重做公式模型、布局或绘制管线。

## 前置条件与待决策

- 043 与 044 的模型、布局和文本岛 API 已完成。
- 跨 TextFlow 选择必须遵循 043 契约；若产品决定启用，先更新 043/数学架构契约并定义失败/撤销语义。

1. 盘点现有 math hit map、selection range、Align 导航与 Qt 输入映射，按成功、边界、拒绝与恢复列出行为缺口。

3. 每个平台分别记录公式类型、输入步骤、期望焦点/选区和实际结果；不可验证项保留为未完成。
4. 更新 011 的总体验收证据，按规范完成分域与独立 final review。

## 风险与回退

数学文本可跨 Run 与双向片段，错误的位置映射可能把鼠标/方向键操作提交到错误的树路径。每次命令须校验 generation、revision、scope 和 UTF-8/字素边界；无法唯一映射时拒绝提交并保留原选区与文档。
