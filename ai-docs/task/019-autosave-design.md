## 范围与非目标

本任务交付 AutoSave 行为规格和后续实现任务，不在此处写 AutoSave 代码。

决策范围包括：开关默认值及作用范围、触发策略、未命名文档的路径选择、已有文件的写回和冲突检测、失败与关闭行为、崩溃后的恢复，以及与手动保存和撤销历史的关系。

不包含恢复界面、永久版本历史、云同步、协作编辑、导入和导出。

## 前置条件与待决策

008 提供文档持久化接口；018 定义会话状态、保存点、异步保存和关闭语义。设计决策如下：

- AutoSave 是持久化的全局用户偏好，默认关闭；每份文档仍独立维护 AutoSave 运行状态。
- 开启 AutoSave 后，只对已有可写 `.cdoc` 路径的文档自动写回。未命名文档必须先选择路径。
- AutoSave 首次启用前不静默写文件，也不把未命名文档自动绑定到 `Documents/caret/Untitled.cdoc` 或隐藏恢复目录。
- 文档和 AutoSave 是不同状态机：文档标题继续使用 018 的 `Edited`、`Saving`、`Saved`；AutoSave 另有关闭、等待路径、等待触发、保存中、失败和冲突状态。

### 开关和路径绑定

| 当前事件 | 文档路径 | 行为 |
| --- | --- | --- |
| 应用启动时偏好为关闭 | 任意 | 不自动保存。 |
| 应用启动时偏好为开启，活动文档已有路径 | `.cdoc` | 不弹窗；对后续编辑启用自动保存。 |
| 应用启动时偏好为开启，活动文档未命名 | 无 | 立即请求另存为。成功后绑定路径并启用；取消则偏好恢复关闭，文档仍为未命名和未保存。 |
| 用户将开关从关闭切到开启 | 已有 `.cdoc` 路径 | 立即启用，不弹另存为。 |
| 用户将开关从关闭切到开启 | 未命名 | 立即弹另存为；成功后才持久化开启偏好并绑定路径。取消则开关回到关闭，偏好不变。 |
| 用户将开关从关闭切到开启 | 多窗口中有多份未命名文档 | 按活动窗口优先依次弹另存为；全部成功才开启。任一取消/失败终止本次流程并保持关闭；此前成功绑定的文档仍保留新路径。 |
| 用户将开关从开启切到关闭 | 任意 | 取消尚未开始的自动保存等待；已进入写入的请求允许完成。关闭开关不撤销已完成写入。 |
| 开启状态下新建未命名文档 | 无 | 新文档建立后立即弹另存为。取消只影响该次开启请求；全局偏好改为关闭，避免开关继续显示开启但新文档不受保护。 |
| 打开已有 `.cdoc` | 有路径 | 保持全局开关值；不因打开文件弹路径窗口。只读安全预览不允许写入，并显示不可自动保存状态。 |

另存为取消时不保留一次性的“已启用但等待路径”状态。AutoSave 的持久化偏好只有在所需路径绑定成功后才提交；失败或取消不会显示启用。多窗口下该偏好为全局值，但保存、路径、generation 和冲突状态按文档会话隔离。用户在多窗口中开启 AutoSave 时，所有未命名文档按活动窗口优先顺序逐一请求路径，避免同时弹出多个模态对话框；全部成功后才提交全局开启。任一取消/失败会终止本次开启流程并保持开关关闭；已经另存成功的文档保留其路径和保存结果，但不自动保存。

开关变更必须先由 `SettingsService` 成功持久化，再将运行时 AutoSave 投影为开启。服务只读/不可用或提交失败时，运行时维持关闭，开关显示关闭并呈现设置错误。若已持久化开启的应用启动时为未命名文档请求路径，用户取消后尝试持久化关闭；若提交失败，保留持久化值，但当前运行仍暂停 AutoSave、显示错误；后续启动可能再次请求路径。开启流程使用独立递增的 operation generation，并捕获待处理的 document/session 集合；切换开关、打开/新建/关闭参与文档等事件会使旧流程失效。过期的文件对话框回调不得重新启用 AutoSave；已完成的另存结果不回滚。

### 触发策略

- 文档命令成功改变内容后，Rust AutoSave 策略记录最新文档 revision，并返回下一次触发的单调时钟 deadline。
- 有输入时使用 1 秒尾沿安静期；持续编辑 30 秒仍未安静时，允许一次最大等待触发。两个值由 Rust 策略集中定义，不散落在 QML 或 C++。
- Qt 在 GUI 事件循环中只设置或重置单次唤醒；deadline 到达时向 Rust 提交带有 session generation 和 deadline generation 的事件。Rust 再校验 AutoSave 状态、文档 revision 和路径后决定是否捕获快照。
- 新编辑会刷新尾沿 deadline；过期或重复的唤醒是无操作。没有待办工作时没有运行中的周期 timer。此处的一次性等待是对用户输入静默期的事件定时，不是轮询。
- 一个文档同时至多有一个写入请求。写入期间产生的多个 revision 合并为最新待保存 revision；当前写入完成后若最新 revision 仍未保存，再按策略安排后续请求。

### 持久化、顺序与状态

- 已命名文档复用现有 Rust 快照、Qt worker 和 `DocumentStorage` 原子替换路径，不另建写入格式。路径由 Rust 应用服务解析，Qt 只执行已授权的文件操作。
- 手动保存和 AutoSave 进入同一文档保存队列，按发起顺序串行写入。手动保存取消未开始的 debounce 并优先捕获当前 revision；已开始的写入不被强行中断。保存完成只推进该快照对应的保存点，不替换当前 Session。
- 保存期间继续编辑时，旧 revision 成功只表示该 revision 已写入。若当前 revision 更新，文档状态仍为 `Edited`，并在当前写入完成后排队保存最新 revision。
- AutoSave 完成当前 revision 的原子写入后，使用 018 的保存点规则显示 `Saved`。写入失败时保存点不前进，文档保留内存内容并显示 `Edited`；AutoSave 错误作为独立状态暴露给标题栏开关的提示，不虚构第四种文档标题状态。
- 同一进程内相同规范化路径由保存队列串行化。跨进程的外部修改检查在替换前重新读取并比对已知基线摘要；检测到差异时禁止 AutoSave 覆盖，进入冲突状态并生成恢复副本。文件被删除、移动或不可读时也不自动重建目标。
- 跨进程基线检查是尽力而为：普通文件系统没有可移植的“仅当内容仍等于摘要时原子替换”接口，检查与原子替换之间仍存在很窄的竞争窗口。实现应尽量缩短该窗口，保留冲突前本地副本，并在 UI 中提供冲突处理入口；不得宣称绝对无丢失保证。文件监听器只能作为提前提示，不能代替写入前验证。
- 手动保存在写前校验时遇到外部修改，也不得静默覆盖。用户可选“另存副本”或“确认替换外部版本”，也可取消。确认替换前必须先把磁盘上的外部版本原始字节原子保存到应用数据恢复区；备份失败则禁止替换。AutoSave 冲突不提供自动替换选项，只能另存或取消冲突处理。

### 失败、重试与关闭

- 写入失败不清空编辑内容、不改变绑定路径和保存点。错误状态保持可见，不进行无界自动重试；下一次有效编辑、用户显式重试或关闭时再尝试。
- 开关关闭不取消已开始的文件替换；迟到结果仍需按 session generation 和 revision 校验。窗口或会话关闭后回调不得更新新文档状态。
- AutoSave 开启时关闭有路径且 dirty 的文档，会立即请求当前 revision 的保存并等待结果；当前 revision 保存成功后可继续关闭。
- 失败、冲突或会话中仍有较新未保存 revision 时，沿用 018 的 Save / Don't Save / Cancel 关闭确认。Save 做显式手动保存并按冲突规则处理；Don't Save 丢弃本会话并移除本会话恢复副本；Cancel 保持文档和恢复副本。
- 未命名文档不能进入开启状态，因此仍按 018 的关闭确认处理；Save 打开另存为。AutoSave 不绕过用户选路径步骤。
- 关闭确认中的手动 Save 遇到冲突时展示“另存副本 / 确认替换外部版本 / Cancel”。替换前先原子备份当前外部文件原始字节；备份或替换失败时保持文档开启并保留本地恢复副本。另存副本成功后切换当前会话路径；确认替换成功后更新该路径的基线摘要和保存点。Cancel 回到关闭确认，文档不关闭。

### 崩溃恢复与清理

- 已命名文档的 AutoSave 直接原子写回原路径；崩溃后最多丢失尚未触发或正在写入的最新编辑，最后一次成功原子写入仍有效。
- 只有发生外部冲突时，应用在拒绝覆盖前把本地最新快照写到本地应用数据目录的恢复区；用户明确替换外部版本时，也先保存磁盘上的原始外部字节。逻辑引用为 `app-local-data:/recovery/`，由宿主注入 Qt `QStandardPaths::AppLocalDataLocation`，不硬编码用户主目录。典型位置为 macOS `~/Library/Application Support/<APPNAME>/recovery`、Windows `%LOCALAPPDATA%/<APPNAME>/recovery`、Linux `~/.local/share/<APPNAME>/recovery`；打包标识或 OS 配置可能影响实际路径，实际位置以 Qt 返回值为准。恢复文件使用单文件 envelope 保存本地 `.cdoc` 快照或外部原始字节、原路径、基线摘要、创建时间和 schema 版本，避免快照与索引分开写导致不一致。
- 恢复 I/O 由 `caret-app` 内独立的 `DocumentRecoveryStorage` 服务负责，单独管理 `recovery/` 子目录、envelope 验证、原子读写和过期清理；AutoSave 协调器只请求服务保存/读取/删除。它复用底层 `atomic_file`，不把恢复保留策略混入通用 `DocumentStorage`，也不为单一应用能力新建 Cargo crate。
- 启动时发现恢复条目则显示恢复选择；恢复不会覆盖原文件，用户可在临时会话中查看并另存为。恢复到临时会话后仍保留 envelope；只有恢复文档另存成功，或用户明确丢弃该恢复条目后才删除。若临时会话再次编辑，必须更新同一个 envelope。恢复失败或取消不得删除。
- 恢复条目保留 30 天；清理仅在应用启动时执行，且只删除已过期、未被恢复流程占用的 Caret 自有条目。清理错误只记录诊断，不影响正常打开或编辑。
- 不为普通临时文档创建隐藏自动恢复副本，因为开启 AutoSave 前已要求绑定用户可见路径。

### 状态转移摘要

```text
Off --开关意图--> Enabling(operation generation)
Enabling --已有路径/偏好提交成功--> Armed
Enabling --未命名--> ChoosingPath --保存并绑定成功--> Enabling/Armed
                                   ├--取消/失败--> Off
                                   └--generation 过期--> Off（迟到回调无效）
Armed --文档变更--> Debouncing --deadline--> Saving(revision)
  ^                                      ├--写入成功，仍为最新--> Armed
  |                                      ├--写入成功，已有更新--> Debouncing
  |                                      ├--外部改变/目标失效--> Conflict
  |                                      └--I/O 失败-----------> Failed
  └--用户重试/新变更------------------------------------------┘
Armed/Debouncing/Failed/Conflict --关闭开关--> Off
任意状态 --Settings 只读/提交失败--> RuntimeOffWithSettingsError
```

成功保存后，文档生命周期状态依然依照 018 的 session revision/savepoint 关系派生，不由此 AutoSave 状态图替代。

## 风险与回退

AutoSave 直接写回用户路径，外部程序可能同时修改目标；实现必须写前校验基线、冲突时拒绝覆盖并保存恢复副本。普通文件系统无法提供可移植的内容比较交换，因此仍存在极窄的跨进程竞争窗口。若实现无法可靠原子保存或保留冲突副本，应保持 AutoSave 关闭并报告错误，不得退化为直接截断目标文件。
