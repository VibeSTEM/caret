## 目标与背景

标题栏已有 AutoSave 开关外观，但目前不执行保存。AutoSave 涉及保存时机、临时文档首次落盘、失败提示和恢复行为；先明确产品与架构规则，再建立独立实现任务。

## 范围与非目标

本任务只产出可执行的 AutoSave 行为规格和后续实现任务，不在此处写 AutoSave 代码。

设计需要明确：

- 默认开关状态、开关保存范围及用户如何知晓当前模式。
- 编辑后何时触发保存：防抖、周期或其他策略；快速连续输入和长时间编辑的语义。
- 临时文档如何命名、保存到哪里，以及第一次自动保存是否需要用户选择路径。
- 已有文件如何自动写回，如何复用原子写入并避免并发覆盖手动保存；目标被外部程序修改、移动或删除时如何检测和处理。
- 保存失败时的状态、重试、通知和关闭行为；失败期间是否继续保留内存内容。
- 应用崩溃或断电后的恢复范围、恢复副本位置、保留期限和清理时机。
- AutoSave 与撤销/重做保存点、手动保存、关闭确认及多个窗口的交互。
- 哪些内容不允许自动写入（例如尚未命名文档或只读资源）。

不包含：实现定时器或写入、恢复 UI、版本历史 UI、云同步和协作编辑。

## 前置条件与待决策

008 提供稳定的文档持久化接口；018 提供文档状态、保存点和关闭语义。产品默认值和恢复保留策略在本设计任务中决策，不从当前视觉开关推断。

## 实施步骤

1. 对照 008、018 和原子保存模型梳理状态与失败路径。
2. 写出开关、触发、临时文件、恢复、冲突和关闭行为决策，并记录未采纳方案及理由。
3. 更新 runtime 与界面规范，确认 Rust 服务、Qt 适配器和 QML 的职责边界。
4. 按决策创建独立 AutoSave 实现任务，列出自动化和真实窗口验收。
5. 独立评审设计及任务边界。

## 风险与回退

自动写入策略可能造成意外覆盖或遗留恢复文件。未决策前保持开关无行为；策略无法兼容原子替换时先调整设计，不降低文档模型的保存保证。
