# 013 — M4：脏段落排版

- 状态：planned
- 依赖：011、012、027
- 优先级：P2
- 创建 / 更新：2026-10-25 / 2026-10-25

## 目标与背景

M0 允许整篇重排。本任务改成普通按键只重排脏段落，并用一份长文档记录重排范围。需求 M4 不设毫秒门禁。数字写进验证表，不写进 CI 失败条件。

## 必读

- [增量排版](../architecture/editor/incremental-layout.md)、[运行时](../architecture/core/runtime.md)
- [测试规范](../standards/testing.md)

## 范围与非目标

为布局缓存补上文档规定的键：`rev`、测量宽度、样式代际，以及表格内的单元格宽度。命令模式、补全、焦点框和选区不进入键。

用一份含标题、公式和表格的长文档，比较一次普通按键前后的重排范围。

不包含：把毫秒数做成 CI 门禁，不包含多线程排版。

## 前置条件与待决策

011 和 012 已 done，且后完成者已按[公式与表格的集成规则](../architecture/editor/math-and-table.md#m3-集成验收)记录单元格公式的集成验收证据。长文档夹具放在 `tests/fixtures/`。

## 实施步骤

1. 按增量排版文档收紧缓存键。多出来的字段要在本任务说明它使哪些编辑失效。
2. 普通文字插入只使所在段落及必要的后续分页失效。
3. 样式代际变化仍使结构和布局整份失效。
4. 记录长文档上的重排范围。不把单次耗时写成门槛。
5. 独立评审确认基准没有把缓存键扩成整篇失效。复验。

## 预计改动

`caret-layout`、`caret-engine` 的失效逻辑，以及 `tests/` 里的夹具和基准入口。基准不进入默认 CTest。

## 验收标准

- [ ] 改一个正文段落不会重排整篇。验证表写出这次实际重排的范围。
- [ ] 改测量宽度或样式代际会按文档失效。
- [ ] 命令模式查询不使布局失效。
- [ ] CI 没有新增按毫秒失败的检查。评审发现已处理。

## 风险与回退

分页变化会使后续页的位置失效，这是必要范围，不算退回整篇重排。若正确性靠整篇重排才能保住，就停在本任务，不把错误结果缓存起来。回退是恢复 M0 的整篇失效，并在验证表说明。
