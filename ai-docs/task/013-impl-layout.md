# 013 — M4：脏段落排版

- 状态：planned
- 依赖：011、012、027
- 优先级：P2
- 创建 / 更新：2026-10-25 / 2026-10-25

## 目标与背景

M0 允许整篇重排。本任务改成普通按键只重排脏段落，并用一份长文档记录重排范围。需求 M4 不设毫秒门禁。数字写进验证表，不写进 CI 失败条件。

## 必读

- [增量排版](../architecture/editor/incremental-layout.md)、[运行时](../architecture/core/runtime.md)
- [测试规范](../standards/testing.md)

## 范围与非目标

为布局缓存补上文档规定的键：段落 `layoutRev`、测量宽度、布局度量样式代际，以及表格内的单元格宽度。命令模式、补全、焦点框、选区和纯绘制属性不进入键。

用一份含标题、公式和表格的长文档，比较一次普通按键前后的重排范围；覆盖长 Paragraph、宽块容器、局部格式变更和 Section 标签宽度变化，记录输入规模、重排段落/页、索引更新范围及必要时的分配/复制量。

不包含：把毫秒数做成 CI 门禁，不包含多线程排版。

## 前置条件与待决策

011 和 012 已 done，且 044 已按[公式与表格的集成规则](../architecture/editor/math-and-table.md#m3-集成验收)完成单元格公式集成并留下验收证据。长文档夹具放在 `tests/fixtures/`。

## 实施步骤

1. 按增量排版文档收紧缓存键。多出来的字段要在本任务说明它使哪些编辑失效。
2. 普通文字插入只使所在段落及必要的后续分页失效。
3. 影响排版度量的全局代际使布局失效；局部度量修改只失效受影响段落和必要的后续分页。纯绘制代际只刷新绘制；大纲语义代际由 010 更新结构索引。
4. 记录长文档上的重排范围。不把单次耗时写成门槛。
5. 独立评审确认基准没有把缓存键扩成整篇失效。复验。

## 预计改动

`caret-layout`、`caret-engine` 的失效逻辑，以及 `tests/` 里的夹具和基准入口。基准不进入默认 CTest。

## 验收标准

- [ ] 改一个正文段落不会重排整篇。验证表写出这次实际重排的范围。
- [ ] 改测量宽度或全局排版度量代际会按文档失效；局部度量修改只失效受影响范围；纯绘制属性不重排。
- [ ] 命令模式查询不使布局失效。
- [ ] Undo 后在旧状态分支编辑不会命中同 ID、相同局部数值但不同内容的缓存；异步旧文档 generation 结果不能覆盖当前快照。
- [ ] 验证表记录长段落、宽容器、局部格式、Section 计数变化的实际重排和索引范围；包含在顶层 Section 前插入以致后续后代标签前缀变化、编号宽度进位的用例；记录数据规模，不把时间或分配数设为未测量的 CI 门槛。
- [ ] CI 没有新增按毫秒失败的检查。评审发现已处理。

## 风险与回退

分页变化会使后续页的位置失效，这是必要范围，不算退回整篇重排。若正确性靠整篇重排才能保住，就停在本任务，不把错误结果缓存起来。回退是恢复 M0 的整篇失效，并在验证表说明。
