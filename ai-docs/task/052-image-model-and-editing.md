# 052 — 图片节点、媒体资源与编辑

- 状态：planned

## 目标与背景

让图片成为可编辑、可保存的 Caret 文档内容，为所有格式导入导出提供统一的图片语义。`.cdoc` 已有媒体资源容器和单资源大小限制，但尚无正文图片节点及编辑契约。

- [页面与段落排版](../architecture/editor/page-layout.md)

## 范围与非目标

- 定义行内图片节点、媒体 ID 引用、替代文本、固有尺寸和文档内显示尺寸。
- 实现插入、替换、调整尺寸、删除、复制粘贴、撤销重做及 `.cdoc` 保存往返。
- 使用现有 `media` 容器和资源限制；资源校验、格式解码、尺寸/像素总量限制及失败清理需定义清楚。
- 图片源内容不执行；远程 URL 不自动下载。格式导入器只允许其任务明确声明的安全包内资源或受限本地相对资源。
- 本任务不实现分页布局、Qt 绘制、浮动/环绕图片和图片编辑器，由 053 负责布局画布，浮动/环绕留后续设计。

## 前置条件与待决策

021 文档树与媒体存储完成。实施前确认支持的栅格/矢量格式、文件大小和解码像素上限、尺寸单位与缩放行为；限值必须来自资源约束而非随意常量。

## 实施步骤

1. 更新文档模型/能力注册表，定义图片节点和媒体资源引用完整性。
2. 实现安全导入、解码验证、原子资源写入及编辑命令。
3. 覆盖 `.cdoc` 往返、撤销、剪贴板、损坏资源和边界尺寸行为。
4. 独立评审模型、安全和资源生命周期后更新记录。

## 预计改动

`caret-doc` 图片与资源验证、`caret-engine` 图片编辑命令、必要的 `caret-app` 文件选择/资源服务；不在 QML 持有文档语义。

## 验收标准

- [ ] 行内图片节点稳定引用媒体资源，支持替代文本与可编辑尺寸。
- [ ] 插入、替换、删除、复制粘贴、撤销重做和保存重开保持引用一致。
- [ ] 畸形/超限图片安全拒绝，失败时不残留孤儿媒体或改变现有文档。
- [ ] 未知图片格式和不可用资源能显示可理解诊断，不静默消失。
- [ ] Rust 行为测试验证资源、文档树与失败副作用；依赖复用审查及独立 review 通过。

## 风险与回退

图片解码的内存和攻击面高于普通文本。限制压缩体积、解码像素总量及格式，并先在临时资源中验证；失败时不插入节点。
