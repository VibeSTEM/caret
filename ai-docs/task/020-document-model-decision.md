## 目标与背景

产品已决定使用 Paragraph/Run 表示文字，并使用可嵌套 EnvironmentNode 表达内容结构和格式作用域。本任务细化 EnvironmentNode 的行内/块级 scope、允许的子节点、背景和删除语义。Paragraph/Run 本身不承担块级层次、自动编号、公式/表格对象和整组删除语义。此决策影响命令、选择、分页、缓存和文件格式，先于实现。

## 范围与非目标

比较并细化段落/Run 富文本树、语义块树加段内 Paragraph/Run、以编辑操作/协作日志为核心的表示。结合用户已选 Paragraph/Run 基础表示，确定语义容器如何组合，而不是重新悬置是否使用 Run。对比结构表达力、编辑复杂度、Unicode 位置、撤销、公式/表格、分页、文件格式演化和缓存。

比较模型和位置方案时，也要评估长文档下的编辑、选区查询、索引更新和内存成本；标出关键操作的复杂度与潜在热点。避免每次小改都复制整棵文档树或扫描无关内容。没有基准前不承诺具体耗时，相关热点由 013/027 的基准与验证补证。

定稿 EnvironmentNode 的 scope（inline/block）、kind、允许的子节点、粗体/斜体嵌套与继承、块级标题/编号、子树删除/提升策略，并区分 PageSection（页面属性）。给出位置契约、其余样式继承、段落标记、块/内联对象边界、稳定 ID 与 rev 使用规则；明确哪些是文档内容、哪些是派生布局。记录版权的一般原则并区分许可证、专利、商业秘密和商标。当前环境高亮行为已定，规范见[结构导航](../architecture/editor/structure-navigation.md)。实现与规格独立编写，不复制 WordCraft 的代码、文档表达或测试。

不包含：实现 crate、采用 docx 为原生格式、协作 CRDT 或 Word 文件兼容承诺。此任务不是法律意见或专利自由实施检索。

## 前置条件与待决策

Paragraph/Run 和嵌套 EnvironmentNode 表示已经选定；块级环境标题采用独立 `title: Option<Paragraph>`；M0 一个 PageSection 覆盖整份正文。标题位置映射、环境 scope 约束、多节扩展、路径和序列化细节仍是草案。完成本任务前不得据其定型生产序列化格式。

## 候选模型对比

以相同场景评估，避免把“段落/Run”误当成与“语义树”互斥的完整模型：Run 解决段内连续文字及字符属性，语义树解决标题、列表、表格和公式等内容结构。

| 候选 | 普通文本与格式 | 空段、公式、表格、分页 | 选择、撤销和文件演化 | 初步判断 |
| --- | --- | --- | --- | --- |
| Paragraph/Run 为主 | 段落由格式连续的 Run 组成，常规富文本编辑直接 | 空段可用段落标记表示；公式需内联对象或特殊 Run；表格需额外容器/递归块；显式分页需专门节点 | Run 合并、拆分和位置映射简单可定义；逐步添加结构时容易让格式载体兼任语义，文件格式可能变成大量特例 | 可作段内文本表示，单独作为整份文档模型偏弱 |
| 语义块树 + 段内格式片段 | 块表达语义，段落内 Run/Span 记录字符格式和空段标记 | 公式为内联对象或数学块；表格是可嵌套块/单元格故事；显式分页为内容标记，自动分页仅为派生结果 | 位置由故事/块路径加段内边界表示；命令按语义节点操作；持久化可独立版本化块种类与属性 | 当前较匹配 Caret 的结构编辑目标，但仍需用实现原型验证复杂编辑与迁移成本 |
| 操作日志/协作序列为主 | 文字与格式由操作及其顺序还原 | 所有结构都可编码为操作，但需处理并发插入、删除和结构冲突 | 天然适合协作/同步；单机编辑、确定性保存、撤销和压缩需额外协议，位置标识与迁移更复杂 | 当前没有协作需求，作为权威持久化模型成本过高；可留作未来同步层而非先验基础 |

当前产品方向是用 Paragraph/Run 保存文本，以 EnvironmentNode 统一表达可嵌套环境；不要为了显得“独特”而回避通用的段落/Run 概念。020 用普通文本、混合格式选区、粗体内斜体、嵌套块级环境、环境标题与自动编号、空段、表格单元格、公式、显式分页和自动分页走查候选树，并定稿尚未确定的结构与迁移规则。高亮和已决定模型的权威描述只维护在架构文档中。

## 验收标准

- [ ] 每个方案覆盖普通文本、格式、空段、表格、公式、显式分页和自动分页。
- [ ] Paragraph/Run 保存文字；EnvironmentNode 同时支持 inline 粗斜体与可嵌套 block 环境，PageSection 单独保存页面属性。
- [ ] M0 恰有一个 PageSection，作用于整份正文；多节范围和分节节点不进入首版格式。
- [ ] `.cdoc` 用顶层 `requiredFeatures` 声明编辑所需能力；未知项允许只读打开、拒绝写入。未知可选字段往返保留；能力标识唯一登记在文档模型规范中。
- [ ] EnvironmentNode kind 仅从内置类型注册表选择；每种类型明确 scope、合法子节点和语义。未知 kind 只读打开，首版 kind 与 feature 标识在文档模型规范登记。
- [ ] 首版 registry 包含行内 Bold/Italic/Font、块级 Section/Showcase；后续类型必须扩展该注册表和兼容能力定义。
- [ ] Font EnvironmentNode 保存局部字体族；Run 不直接保存字体族；未由环境、文档全局覆盖或主题指定时才使用系统默认文本字体。
- [ ] Font 环境按字体族覆盖嵌套；同族相邻/冗余范围合并或压平，不同族嵌套保留。
- [ ] 格式完整优先级为 Run/Paragraph 局部显式属性 → EnvironmentNode 设置 → 文档全局覆盖 → 主题命名样式 → 应用默认值。
- [ ] 文档级全局设置选择文档排版主题和默认 Run/Paragraph 样式，并可设置全局格式覆盖；`.cdoc` 保存主题当前格式快照并可记录来源 ID。运行时只支持一个主题格式，加载旧主题/快照时迁移到当前结构，不并行保留旧版本逻辑。
- [ ] 新建文档的 `defaultFontFamily` 未设置；字体解析先看主题默认样式，再回退到系统默认文本字体。默认字体命令才写入显式全局覆盖。
- [ ] 旧主题/快照载入时迁移到当前结构；外部主题源文件只在用户显式保存时写回，已有文档只在显式更新时替换快照。
- [ ] 粗体和斜体只有行内 EnvironmentNode 一种持久化表示，Run 不保存这两种直接覆盖。
- [ ] 粗体与斜体可互相嵌套，同类粗体/斜体环境不嵌套且相邻范围规范化合并，其他语义环境不自动合并；拆分时原 ID 留左段、合并保留靠前 ID，撤销恢复原节点和 ID。
- [ ] 样式变更按布局度量、纯绘制、大纲语义和来源元数据分类并只使相应缓存失效；纯字色不重排也不重建结构索引。布局键使用稳定节点 ID 加局部 `layoutRev`，结构索引使用 `structureRev` 和大纲样式代际，避免修订号碰撞或无关重建；局部编辑只复制受影响节点。
- [ ] 当前环境高亮遵循[结构导航](../architecture/editor/structure-navigation.md)的唯一行为定义。
- [ ] 环境删除与提升子项边界明确。
- [ ] 文档内容/派生布局、UTF-8 偏移/字素移动、稳定 ID/缓存 rev 边界明确。
- [ ] Rust 位置以 UTF-8 字节偏移为准，键盘移动按字素簇；Qt/C++ UTF-16 只在 FFI 边界转换。
- [ ] 位置块路径使用稳定节点 ID；节点移动保留 ID，删除/替换由事务提供位置映射。
- [ ] 块级 EnvironmentNode 的独立标题 Paragraph 可通过稳定节点 ID 定位，且不属于 `children`。
- [ ] 块环境标题保持单段；标题中 Enter 将后半段移入新建的正文首段并插到现有内容前，正文为空或后缀为空时也创建对应 Paragraph。
- [ ] 一般版权原则有辖区边界；没有绝对无侵权保证。
- [ ] 021–027 无依赖环且分别可验收；独立评审通过。
