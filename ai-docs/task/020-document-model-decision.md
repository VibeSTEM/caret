## 目标与背景

产品已决定使用 Paragraph/Run 表示文字，并使用可嵌套 EnvironmentNode 表达内容结构和格式作用域。本任务细化 EnvironmentNode 的行内/块级 scope、允许的子节点、背景和删除语义。Paragraph/Run 本身不承担块级层次、自动编号、公式/表格对象和整组删除语义。此决策影响命令、选择、分页、缓存和文件格式，先于实现。

## 范围与非目标

比较并细化段落/Run 富文本树、语义块树加段内 Paragraph/Run、以编辑操作/协作日志为核心的表示。结合用户已选 Paragraph/Run 基础表示，确定语义容器如何组合，而不是重新悬置是否使用 Run。对比结构表达力、编辑复杂度、Unicode 位置、撤销、公式/表格、分页、文件格式演化和缓存。

比较模型和位置方案时，也要评估长文档下的编辑、选区查询、索引更新和内存成本；标出关键操作的复杂度与潜在热点。避免每次小改都复制整棵文档树或扫描无关内容。没有基准前不承诺具体耗时，相关热点由 013/027 的基准与验证补证。

定稿 EnvironmentNode 的 scope（inline/block）、kind、允许的子节点、粗体/斜体嵌套与继承、块级标题/编号、子树删除/提升策略，并区分 PageSection（页面属性）。给出位置契约、其余样式继承、段落标记、块/内联对象边界、稳定 ID 与 rev 使用规则；明确哪些是文档内容、哪些是派生布局。记录版权的一般原则并区分许可证、专利、商业秘密和商标。当前环境高亮行为已定，规范见[结构导航](../architecture/editor/structure-navigation.md)。实现与规格独立编写，不复制 WordCraft 的代码、文档表达或测试。

不包含：实现 crate、采用 docx 为原生格式、协作 CRDT 或 Word 文件兼容承诺。此任务不是法律意见或专利自由实施检索。

## 前置条件与待决策

Paragraph/Run 和嵌套 EnvironmentNode 表示已经选定；块级环境标题采用独立 `title: Option<Paragraph>`；M0 一个 PageSection 覆盖整份正文。多节扩展和生产 `.cdoc` 序列化细节仍待实现任务验证；完成本任务前不得据其定型生产文件格式。

## 候选模型对比

以相同场景评估，避免把“段落/Run”误当成与“语义树”互斥的完整模型：Run 解决段内连续文字及字符属性，语义树解决标题、列表、表格和公式等内容结构。

| 候选 | 普通文本与格式 | 空段、公式、表格、分页 | 选择、撤销和文件演化 | 初步判断 |
| --- | --- | --- | --- | --- |
| Paragraph/Run 为主 | 段落由格式连续的 Run 组成，常规富文本编辑直接 | 空段可用段落标记表示；公式需内联对象或特殊 Run；表格需额外容器/递归块；显式分页需专门节点 | Run 合并、拆分和位置映射简单可定义；逐步添加结构时容易让格式载体兼任语义，文件格式可能变成大量特例 | 可作段内文本表示，单独作为整份文档模型偏弱 |
| 语义块树 + 段内格式片段 | 块表达语义，段落内 Run/Span 记录字符格式和空段标记 | 公式为内联对象或数学块；表格是可嵌套块/单元格故事；显式分页为内容标记，自动分页仅为派生结果 | 位置由故事/块路径加段内边界表示；命令按语义节点操作；持久化可独立版本化块种类与属性 | 当前较匹配 Caret 的结构编辑目标，但仍需用实现原型验证复杂编辑与迁移成本 |
| 操作日志/协作序列为主 | 文字与格式由操作及其顺序还原 | 所有结构都可编码为操作，但需处理并发插入、删除和结构冲突 | 天然适合协作/同步；单机编辑、确定性保存、撤销和压缩需额外协议，位置标识与迁移更复杂 | 当前没有协作需求，作为权威持久化模型成本过高；可留作未来同步层而非先验基础 |

### 共同场景走查

| 场景 | Paragraph/Run 为主 | 语义块树 + Paragraph/Run | 操作日志为主 |
| --- | --- | --- | --- |
| 普通文本、混合格式和空段 | Run 分段明确；空段需保存段落标记格式 | Paragraph 是稳定块，空段和段落属性自然归位 | 必须把插入、格式变更和段落边界都编码成操作 |
| 粗斜体嵌套、环境边界 | 用行内树包装 Run；越多语义越容易让格式载体兼任结构 | EnvironmentNode 明确 scope，ID 和边界亲和性可用于定位/撤销 | 操作需记录局部拆分/合并与位置映射，撤销依赖操作语义 |
| Section 标题、层级编号、Showcase 删除/解除 | 需额外为 Run/Paragraph 增加拥有子项和编号约定 | Section 明确拥有标题和子树，编号是派生标签，解除有原子提升规则 | 需定义移动/删除容器时对后续操作和 ID 的映射 |
| 表格单元格、公式 | 可扩展，但会引入段落内部特例和多段容器 | Table/公式是有类型的块/行内对象，可用稳定 ID 路径定位 | 表格结构编辑会产生大量相互依赖的操作和冲突边界 |
| 显式分页与自动分页 | 两者需额外区分持久内容和版面结果 | 显式分页是内容节点；自动分页只在布局结果 | 同样需区分用户操作与重排派生结果，重算本身不应进日志 |
| Unicode 位置与混合方向文字 | 字节偏移适合存储，仍需独立的段落/容器路径和 cluster 映射 | 有类型路径 + UTF-8 偏移 + 边界亲和性，cluster/glyph 仅是布局映射 | 位置 ID 适合并发，但单机编辑需要额外锚点维护和压缩 |
| 长文档局部编辑、选区查询和结构索引 | 可以按段落定位，但结构语义混入 Run 后，索引可能需要扫描格式树 | 稳定 ID 与块/段索引支持限定更新范围；共享未改节点，位置映射只覆盖受影响子树 | 插入/删除会维护位置 ID 与历史映射；需测量索引和墓碑的空间成本 |
| 增量布局、撤销和文件演化 | 可以按段落局部更新，但结构扩展容易导致规则散落 | 稳定块 ID 和分类 rev 可复用缓存；结构种类可独立版本化 | 追加历史方便协作，需快照压缩、重放和格式迁移协议 |

结论：Paragraph/Run 适合作为段内文本表示；文档结构由语义块树拥有；操作日志不作为首版权威存储。自动分页始终为派生数据；表格/公式与显式分页各自保留明确节点类型。

### 局部操作成本假设

以下是用平坦 `String`/`Vec` 表示时应公开承认的成本，不是性能门槛或最终容器选型。热路径不得扫描无关文档节点；基准决定是否引入分块文本、区间索引或分块子项容器。

| 操作 | 朴素平坦表示的上界 | M0/M4 要验证的局部性 |
| --- | --- | --- |
| UTF-8 文本插入/删除、重算段落字素边界 | O(P)，P 为段落字节数；尾部搬移或全段重分段可达段落线性成本 | 不扫描其他 Paragraph；测量长 Paragraph 并据此决定增量分段/分块文本 |
| 范围格式化/查询 | O(R + P)，R 为范围内 Run/环境数；更新平坦 `Vec` 可能移动同段落后缀 | 仅访问相交节点和必要边界；查询与修改使用同一字素边界索引 |
| 稳定 ID 到当前位置/路径解析 | 有 ID 索引时 O(depth)，无索引时最坏 O(N) 文档节点 | 编辑和命中热路径不允许为 ID 扫描全文；结构改写增量维护受影响索引 |
| 子树移动、解除和位置映射 | O(S + W)，S 为被搬子树，W 为源/目标平坦子项数组宽度 | 不复制无关子树；映射只为受影响位置构造，测量宽容器 |
| Section 重新编号 | O(A + D)，A 为受影响计数流的后续 Section，D 为这些 Section 下编号标签受祖先前缀变化影响的后代 | 只重算受影响计数流的序号，但刷新其标签及后代前缀；标签宽度变化使相应标题布局失效 |

这些上界说明为什么 `Arc` 共享本身不是局部编辑复杂度保证；任何更强的性能声称都必须由基准数据支持。

当前产品方向是用 Paragraph/Run 保存文本，以 EnvironmentNode 统一表达可嵌套环境；不要为了显得“独特”而回避通用的段落/Run 概念。上方共同场景矩阵是候选模型走查清单；字段与行为的权威描述只维护在[文档模型](../architecture/editor/document-model.md)，当前环境高亮见[结构导航](../architecture/editor/structure-navigation.md)。

## 验收标准

- [x] 每个方案覆盖普通文本、格式、空段、表格、公式、显式分页和自动分页。
- [x] Paragraph/Run 保存文字；EnvironmentNode 同时支持 inline 粗斜体与可嵌套 block 环境，PageSection 单独保存页面属性。
- [x] M0 恰有一个 PageSection，作用于整份正文；多节范围和分节节点不进入首版格式。
- [x] `.cdoc` 用顶层 `requiredFeatures` 声明编辑所需能力；未知项允许只读打开、拒绝写入。未知可选字段往返保留；能力标识唯一登记在文档模型规范中。
- [x] EnvironmentNode kind 仅从内置类型注册表选择；每种类型明确 scope、合法子节点和语义。文档主题可替换每种 kind 的默认环境模板并定义同 kind 变体；实例可选 `definitionId`，其 `baseKind` 必须匹配，实例 `props` 作局部覆盖。模板可组合既有格式环境和样式值，但不展开成文档子树，也不能改写结构语义。未知 kind 只读打开，首版 kind 与 feature 标识在文档模型规范登记。
- [x] 首版环境模板使用声明式数据，可组合内置格式环境、命名样式和覆盖值；不执行用户脚本或通用宏语言。
- [x] 首版 registry 包含行内 Bold/Italic/Font、块级 Section/Showcase；后续类型必须扩展该注册表和兼容能力定义。
- [x] Font EnvironmentNode 保存局部字体族；Run 不直接保存字体族；未由环境、文档全局覆盖或主题指定时才使用系统默认文本字体。
- [x] Font 环境按字体族覆盖嵌套；同族相邻/冗余范围合并或压平，不同族嵌套保留。
- [x] 格式完整优先级为 Run/Paragraph 局部显式属性 → EnvironmentNode 有效设置（实例覆盖模板，内层向外继承）→ 文档全局覆盖 → 主题命名样式 → 应用默认值。
- [x] 文档级全局设置选择文档排版主题和默认 Run/Paragraph 样式，并可设置全局格式覆盖；`.cdoc` 保存主题当前格式快照并可记录来源 ID。运行时只支持一个主题格式，加载旧主题/快照时迁移到当前结构，不并行保留旧版本逻辑。
- [x] 新建文档的 `defaultFontFamily` 未设置；未由环境、全局覆盖或主题指定时才使用系统默认文本字体。默认字体命令才写入显式全局覆盖。
- [x] 旧主题/快照载入时迁移到当前结构；外部主题源文件只在用户显式保存时写回，已有文档只在显式更新时替换快照。
- [x] 粗体和斜体只有行内 EnvironmentNode 一种持久化表示，Run 不保存这两种直接覆盖。
- [x] 粗体与斜体可互相嵌套；`enabled: true|false` 分别显式开启/关闭，缺少节点表示继承，同状态且元数据相同的同类环境才压平；相邻范围仅在兼容时合并，其他语义环境不自动合并。若序列化显式状态，`.cdoc` 声明 `caret.env.explicit-format-state`。拆分时原 ID 留左段、合并保留靠前 ID，撤销恢复原节点和 ID。
- [x] 样式变更按布局度量、纯绘制、大纲语义和来源元数据分类并只使相应缓存失效；纯字色不重排也不重建结构索引。布局键使用稳定节点 ID 加局部 `layoutRev`，结构索引使用 `structureRev` 和大纲样式代际，避免修订号碰撞或无关重建；局部编辑只复制受影响节点。
- [x] 当前环境高亮遵循[结构导航](../architecture/editor/structure-navigation.md)的唯一行为定义。
- [x] Section 持有编号定义；顶层按文档顺序编号，嵌套 Section 依据 Section 祖先生成层级编号，只拼接启用编号的祖先，普通容器不打断计数。模板提供默认显示开关与逐层格式，实例可覆盖；格式至少支持阿拉伯数字、小写/大写罗马数字和中文数字。关闭编号时不生成标签且不占用同级序号。模板不能改变层级/计数关系。编号是标题前的虚拟标签，不是持久化 Run、不计入文本偏移；解除时物化为普通文字。块环境整体删除移除标题和整棵子树；解除环境保留标题并将其转成首个普通 Paragraph，再按原顺序提升正文子项，保留子节点和标题 Paragraph 的 ID。
- [x] 文档内容/派生布局、UTF-8 偏移/字素移动、稳定 ID/缓存 rev 边界明确。
- [x] 文档默认语言、Paragraph 覆盖、Run 局部覆盖按 BCP 47 标签解析；应用界面语言独立，自动检测不静默修改正文或持久化语言标签。
- [x] Run 在插入、加载和保存时保留原始 Unicode 码点序列；需要规范化搜索/比较时另算视图，不回写正文。
- [x] Rust 位置以 UTF-8 字节偏移为准，键盘移动按同一 Unicode 版本的 extended grapheme cluster；Qt/C++ UTF-16 只在 FFI 边界转换。
- [x] 行内环境边界上的 Pos 携带 upstream/downstream 亲和性，并决定插入文本继承的环境链；环境两侧呈现“无环境｜有环境｜无环境”。点击按命中的字素侧选 affinity，歧义精确边界选 downstream；简单 LTR 边界的方向键切换表见文档模型，向外时同偏移切换并更新高亮/格式状态，从外侧向内移动时跨过相邻字素簇并落在内侧，工具栏与选区命令保留 affinity。
- [x] 位置块路径使用有类型的 `EnvironmentBody`、`TableCell`、`Paragraph` 和 `EnvironmentTitle` 段，均使用稳定 ID、不使用数组下标；解析时验证段类型和包含关系。节点移动保留 ID，删除/替换由事务提供位置映射。
- [x] 块级 EnvironmentNode 的独立标题 Paragraph 可通过稳定节点 ID 定位，且不属于 `children`。
- [x] 块环境标题保持单段；标题中 Enter 将后半段移入新建的正文首段并插到现有内容前，正文为空或后缀为空时也创建对应 Paragraph。
- [x] 一般版权原则有辖区边界；没有绝对无侵权保证。
- [x] 021–027 的任务依赖无环，各任务均有独立目标和验收标准。
- [x] 属性归属按目标 kind 白名单校验；粗体/斜体可由主题/环境继承，同时有且仅有 EnvironmentNode 能持久表达显式关闭，不恢复 Run 粗斜体属性；`enabled: true|false` 分别显式开启/关闭。
- [x] 相交格式区间用字素边界切分并树化；新范围置于已有环境链的内侧以保留已有模板优先级；单次同时创建多种环境时按 Bold → Italic → Font 嵌套，不跨命令重排已有祖先。树形可依命令顺序不同，但各自语义确定；同值冗余判定、definition/props 合并条件和 Undo ID 恢复明确。
- [x] 同一 Paragraph 的字素分段跨 Run 与行内格式环境；样式边界不制造停靠点，行内对象是原子边界；交互选区向外吸附到完整字素，非法 API 偏移明确拒绝。
- [x] 逻辑边界亲和性与视觉 caret affinity 分离；权威 Pos 以 story ID、终止稳定节点 ID、UTF-8 偏移为锚，类型路径可重建；跨父移动、拆分、合并、解除和删除均有位置映射。
- [x] Section 计数流按最近已编号祖先和显示层级共享，Showcase/未编号 Section 对标签和计数透明；无标题 Section 不显示标签、不占号但对后代透明；批量解除先快照编号再原子改树。标题 Enter 覆盖标题首尾、标题内选区、跨标题/正文选区和 IME composition 边界。
- [x] 未知必需能力与主题迁移有安全预览边界；未知内容不被静默遗漏，未来主题版本/缺少迁移器不猜测，迁移先在副本验证再安装。
- [x] `contentRev`/`layoutRev`/`structureRev`/`paintRev` 的 Undo 分支不复用令牌；性能目标不由 `Arc` 共享推断，基准覆盖长 Paragraph、宽容器、局部编辑、选区/路径查询和 Section 重编号。
- [x] 独立评审通过；最终复审未发现未处理的 P1/P2。

## 独立评审发现与处理

2026-10-25 的只读评审确认 Paragraph/Run + 语义树无需推倒重来，但以下不变量需在 M0 实现前定稿：

1. **属性归属与关闭**：已按用户决定采用环境级 `enabled: true|false`；Run 不保存粗斜体覆盖，缺少该 kind 节点表示继承，false 遮蔽主题/祖先开启，内层 true 可重新开启。
2. **相交范围**：格式区间不能在树中交叉；操作在合法字素边界切分，新环境放在目标叶片段的最内层以保留既有祖先和模板优先级；只有单次操作一起创建的多个环境才使用稳定 kind 顺序 Bold → Italic → Font。不同命令顺序可生成不同树；Font=A 内含 Font=B、Bold=on 内含 Bold=off 都不是冗余。
3. **文本边界与光标**：分段基于 Paragraph 的逻辑文本，跨 Run/行内环境；逻辑环境亲和性只决定输入继承，视觉方向与 bidi caret 由布局单独映射。
4. **位置和编号**：用稳定终止节点 ID 锚定位置、从树索引重建路径；所有结构改写返回映射。计数域已明确按最近已编号祖先和显示层级共享；缺标题 Section 不显示且不计数，解除时不合成标题。
5. **兼容预览**：未知能力不代表已正确打开；明确占位、提示、保存和导出限制。未来主题结构仅迁移已知旧版本，失败不得替换原快照。
6. **成本与缓存**：结构共享不代表宽 Vec/长 Paragraph 编辑免费；Undo 后新分支必须使用不重复修订令牌，异步布局结果仍以文档 generation 防旧结果覆盖。

首轮评审列出的设计缺口已写入架构规范和实现验收。中间复审发现的模板优先级及 Section 后代重排问题也已修复；未知可选字段在节点变换时的保真要求已加入 021。Showcase 编号透明、未编号祖先省略、关闭编号不占号、字素内位置非法、标题空后缀、文件打开失败保留有效文档及主题更新失败保留旧快照均保持原决定。最终独立评审通过，未发现未处理的 P1/P2，020 满足关闭条件。

### 定稿边界示例

#### Section 计数域

```text
Section 1
├── Section（编号关闭）A
│   └── Section（编号开启）X
└── Section（编号关闭）B
    └── Section（编号开启）Y
```

- X/Y 共用最近已编号祖先 `1` 的下一层计数域，显示 `1.1`、`1.2`，不按未编号直接父节点重启计数。
- 若树中没有已编号祖先，第一条启用编号的后代进入文档级计数流，从下一个可用顶层序号开始。
- `title: None` 的 Section 不显示标签、不占自身序号，作为结构容器对编号透明；空标题 Paragraph 则显示标签并占号。

Showcase 同样对编号路径与计数流透明。关闭编号的 Section 仍有结构语义，但其编号后代跳过它，并按最近已编号祖先的显示层级接续计数。

#### 标题 Enter 的边界

- 光标位于标题开头/末尾时，按既定规则保留空标题前缀或创建空正文后缀段。
- 标题内选区 Enter 可按“删除选区后在其起点拆分”一次提交；跨标题与正文的选区若不能原子映射，则拒绝且保持原文、选区和 IME 状态不变。
- Return 尚用于 IME candidate 时先由输入法消费；composition 提交后再次 Return 才执行 Enter 命令。

这些规则用于实现前封口 020/022：标题内选区先被替换再拆分；跨标题/正文选区原子拒绝；IME composition 未提交时由输入法先处理 Return。
