## 目标与背景

产品已决定使用 Paragraph/Run 表示文字，并使用可嵌套 EnvironmentNode 表达内容结构和格式作用域。本任务细化 EnvironmentNode 的行内/块级 scope、允许的子节点、背景和删除语义。Paragraph/Run 本身不承担块级层次、自动编号、公式/表格对象和整组删除语义。此决策影响命令、选择、分页、缓存和文件格式，先于实现。

## 范围与非目标

比较并细化段落/Run 富文本树、语义块树加段内 Paragraph/Run、以编辑操作/协作日志为核心的表示。结合用户已选 Paragraph/Run 基础表示，确定语义容器如何组合，而不是重新悬置是否使用 Run。对比结构表达力、编辑复杂度、Unicode 位置、撤销、公式/表格、分页、文件格式演化和缓存。

定稿 EnvironmentNode 的 scope（inline/block）、kind、允许的子节点、粗体/斜体嵌套、块级标题/编号，以及当前环境背景高亮规则和子树删除/提升策略；并区分 PageSection（页面属性）。给出位置契约、样式继承、段落标记、块/内联对象边界、稳定 ID 与 rev 使用规则；明确哪些是文档内容、哪些是派生布局。记录版权的一般原则并区分许可证、专利、商业秘密和商标。实现与规格独立编写，不复制 WordCraft 的代码、文档表达或测试。

不包含：实现 crate、采用 docx 为原生格式、协作 CRDT 或 Word 文件兼容承诺。此任务不是法律意见或专利自由实施检索。

## 候选模型对比

以相同场景评估，避免把“段落/Run”误当成与“语义树”互斥的完整模型：Run 解决段内连续文字及字符属性，语义树解决标题、列表、表格和公式等内容结构。

| 候选 | 普通文本与格式 | 空段、公式、表格、分页 | 选择、撤销和文件演化 | 初步判断 |
| --- | --- | --- | --- | --- |
| Paragraph/Run 为主 | 段落由格式连续的 Run 组成，常规富文本编辑直接 | 空段可用段落标记表示；公式需内联对象或特殊 Run；表格需额外容器/递归块；显式分页需专门节点 | Run 合并、拆分和位置映射简单可定义；逐步添加结构时容易让格式载体兼任语义，文件格式可能变成大量特例 | 可作段内文本表示，单独作为整份文档模型偏弱 |
| 语义块树 + 段内格式片段 | 块表达语义，段落内 Run/Span 记录字符格式和空段标记 | 公式为内联对象或数学块；表格是可嵌套块/单元格故事；显式分页为内容标记，自动分页仅为派生结果 | 位置由故事/块路径加段内边界表示；命令按语义节点操作；持久化可独立版本化块种类与属性 | 当前较匹配 Caret 的结构编辑目标，但仍需用实现原型验证复杂编辑与迁移成本 |
| 操作日志/协作序列为主 | 文字与格式由操作及其顺序还原 | 所有结构都可编码为操作，但需处理并发插入、删除和结构冲突 | 天然适合协作/同步；单机编辑、确定性保存、撤销和压缩需额外协议，位置标识与迁移更复杂 | 当前没有协作需求，作为权威持久化模型成本过高；可留作未来同步层而非先验基础 |

当前产品方向是用 Paragraph/Run 保存文本，以 EnvironmentNode 统一表达可嵌套环境；不要为了显得“独特”而回避通用的段落/Run 概念。020 仍须走查普通文本、混合格式选区、粗体内斜体、嵌套块级环境和光标高亮、环境标题自动编号、空段、表格单元格、公式、显式分页和自动分页，并确定 inline/block 子节点约束、当前环境判定与高亮范围、删除/提升子项、位置、稳定 ID、格式继承、事务失败和迁移规则，再把细化结果写成架构决议。

### 已确定模型的结构场景

| 场景 | 文档结构 | 用户可见行为 |
| --- | --- | --- |
| 普通正文 | `Paragraph { inlines: [Run(text, characterProps), ...], props }` | 同段可以有多种字符格式，光标/选区仍落在文字范围上 |
| 行内格式环境 | Paragraph 的 inline 列表可包含 `EnvironmentNode(kind: Bold/Italic)`，子项为 Run 或其他行内环境 | 粗体内可嵌斜体，继承按外到内合并；离开作用域恢复父格式；格式命令可对范围包裹/解除该环境 |
| 可显式删除的块环境 | `EnvironmentNode { kind, title?, numberingRef?, children: [Block, ...] }` | 标题是 Paragraph/Run；环境可嵌套。光标进入时由视图高亮当前最内层环境；子节点规则由 kind/scope 限制 |
| `1.` 与较大标题字 | 章节类块环境引用 `NumberingDef`；标题 Paragraph 引用标题样式；Run 只存用户输入的标题文字 | `1.` 根据同级章节顺序生成，字号从样式解析；插入/移动章节可重编号，不能靠解析标题文本或把序号拼进 Run |
| 删除块环境 | `environment.delete(id, mode)` 是结构命令 | `delete_subtree` 删除环境和子内容；明确的 `lift_children` 模式可保留子内容并提升一级。行内粗体/斜体环境只处理其文字范围。不能把两种行为藏在普通 Delete 键里 |
| 空段 | 没有文字 Run 的 Paragraph，仍有段落属性和段落标记样式 | 允许空段存在并参与光标移动与行高；不靠插入空格占位 |
| 表格与公式 | Table 是容纳行/格/块的结构块；公式是有类型的内联对象或数学块 | 表格和公式不是用普通文本 Run 模拟的标记串 |
| 分页 | 显式分页是文档块/标记；自动分页只在布局快照中 | 删除自动分页结果不删文档内容；用户插入的分页符可被结构命令删除 |

这说明 Paragraph/Run 能承担标题文本和格式，但层级、自动编号以及“删除整段子树”需要块级 EnvironmentNode 和结构命令。粗体/斜体也可以是行内 EnvironmentNode，它们有文字范围但不拥有块级背景。PageSection 只承载纸张几何，不是内容环境。

嵌套示例：

```text
EnvironmentNode(kind: Showcase, scope: block)
├── Paragraph(title: "Showcase")
└── EnvironmentNode(kind: Rationale, scope: block)
    └── Paragraph
        └── EnvironmentNode(kind: Bold, scope: inline)
            └── Run("重点")
```

光标位于 Rationale 的 Paragraph 中时，Rationale 是最内层当前环境，视图高亮它的容器；离开后高亮随新光标位置更新。若光标位于粗体行内环境中，行内环境范围获得背景高亮。环境节点本身不保存这个光标高亮，也不把它写入文件或打印。
