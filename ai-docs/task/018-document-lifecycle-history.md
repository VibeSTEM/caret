## 目标与背景

文档标题栏需要反映实际生命周期，不能根据是否选择了保存路径就显示为已保存。Rust 文档会话/应用服务权威持有文档内容、dirty 状态、保存点和编辑历史；Qt ViewModel 跟踪待完成的文件操作数，并据此投影 Saving 状态，QML 只显示投影状态并提交用户选择。修改过的文档关闭时必须由用户决定保存、不保存或取消。

## 范围与非目标

- 状态至少覆盖临时未修改、已修改、保存中、已保存；保存失败回到已修改并保留错误信息。标题和状态栏都来自同一会话状态。
- 已修改时标题格式为“文件名 — Edited”；临时文档显示“Untitled — Edited”。保存中相应显示“文件名 — Saving”，保存成功显示“文件名 — Saved”。
- 标题栏显示自动保存开关、打开、保存、撤销、重做、Comments、Edit/Review/View 模式菜单、Share、单图标搜索和设置；文件名居中。第二行显示 Home 标签，与首行之间不加分隔线。本任务只交付模式选择 UI，不实现各模式权限与修订行为。沿用当前图标风格；为新控件补齐必要资源，统一替换图形留给 036。
- 首次保存的临时文档执行本地“另存为”，默认目录为 `Documents/caret`；建议文件名从 `Untitled.cdoc` 开始，若已存在则依次建议 `Untitled-1.cdoc`、`Untitled-2.cdoc` 等未占用名称。写入成功后绑定所选路径。
- 已有文件点保存时直接写回原路径。保存成功后才转为已保存。
- 保存请求捕获开始时的文档 revision。异步写入完成只回报该 revision 的结果并更新对应保存点，不替换当前会话；期间产生的新编辑继续标为未保存。
- 同一会话对同一已解析目标路径的连续保存按发起顺序串行，较旧 revision 不得在较新 revision 之后覆盖文件。
- 关闭已修改文档时显示应用内样式的确认窗口，按钮顺序为“Save / Don't Save / Cancel”，不显示关闭图标。Save 先关闭确认窗口，再打开另存为或写入已有路径；只有当前 revision 已保存后才关闭文档。若保存期间又有新编辑，窗口保持打开并显示未保存状态。失败保留窗口和修改；取消保持窗口打开；不保存关闭并丢弃本次会话。
- 建立仅驻留内存的分叉撤销/重做历史：撤销后继续编辑会保留旧未来并创建分支；连续输入可合并；保存位置可标记；历史随文档会话关闭而释放，不写入 `.cdoc`。使用 `undo` crate 的树形 `History` 管理分支、保存点和编辑合并；Caret 自己实现领域编辑的紧凑可逆变更，不得按每次编辑复制整份文档。历史容量还需按总记录内存约束，不能只限制当前分支的编辑数。
- 撤销回到最近保存的内容时显示已保存状态；重做越过保存点后恢复已修改状态。保存失败不能推进保存点。

不包含：多分支编辑、协作合并、永久审计日志、跨文档撤销、版本浏览器 UI。
AutoSave 策略不在本任务设计或实现，单独由 019 先行设计。

## 风险与回退

历史记录仅复制受影响段落，不保存整份文档；特别长的单段仍会增加单条编辑记录的复制与内存成本。当前以操作数和估算字节双重设限，超限只清理历史，不改变当前文档。估算包含已知段落、行内节点和未知 JSON 字段，并对容器开销留有余量；分配器实现导致的精确占用不能从模型层精确测得。若长段落实测仍有明显成本，后续应改为局部文本逆补丁。

- 2026-10-28：用户确认历史应使用类似 Git 的分叉树，而非撤销后丢弃 redo；历史不跨软件生命周期持久化。默认保存名若已存在，依次建议 `Untitled-1.cdoc`、`Untitled-2.cdoc` 等未占用名称。研究发现 Rust `undo` crate 提供可合并的编辑命令、分叉 `History`、保存点及按编辑数量限制；实施时仍须用紧凑反向变更控制实际内存，不存全文快照。
- 2026-10-28：评估 `undoredo` 后决定采用 `undo`。`undoredo` 能为自定义结构生成稀疏 delta，也支持历史树；但当前 Caret 由领域命令直接修改有序 `Vec`、嵌套节点和 `String`，接入它需要把编辑统一改为 Recorder 操作，并为有序树和文本位置映射补自定义 delta。这样会改动现有编辑边界，却没有消除 Caret 必须维护的领域逆操作。`undo::History` 已提供分支、保存点和 `Edit::merge` 等管理能力，Caret 只需实现紧凑的领域编辑记录，较符合现有结构。`undo` 的分支历史容量限制不能视作总字节上限，必须另行统计并回收记录。
- 2026-10-28：按用户要求在本次 shell 改动中加入 Editing、Review、View 模式菜单及所需图标资源，暂沿用当前图标风格；用户计划在 036 中统一替换图形。三种模式的权限、审阅记录和持久化语义拆到 035，不在本任务中实现。
