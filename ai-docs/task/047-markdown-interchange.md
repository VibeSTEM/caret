## 目标与背景

实现 Markdown 的完整 Caret 内容导入导出。只有 Caret 所有文档节点、资源、排版和画布行为均已实现后才能开工；不先做文本子集。Caret 文档树是唯一规范 AST；不另建通用交换 AST。架构边界见[文档格式导入与导出](../architecture/editor/document-interchange.md)。

## 范围与非目标

- 定义格式适配器的导入、导出结果及结构化转换诊断。
- 导入到临时文档，验证通过并取得用户对降级报告的确认后，才安装新会话。
- 导出写新目标文件，不修改源文档绑定路径和保存状态。
- 等待所有依赖完成后建立转换生命周期、诊断与 Caret Markdown 方言，并覆盖 Caret 支持的所有正文节点、格式、表格、公式、图片和资源。
- 记录并固定 Markdown 输入兼容范围及导出方言；不支持的源格式功能须报告与确认。
- 不负责先行补齐 Caret 语义/画布能力；分别由 010–027、050–053 完成。

## 前置条件与待决策

- 010–027 中相关模型、塑形、页面、段落布局、格式和画布任务，以及 011、012、050–053 全部验收完成；Caret 支持的内容集合冻结后才开始格式转换。
- 不支持语法必须报告，不能静默删除或伪装成无损转换。

## 实施步骤

1. 核验 CommonMark Rust 库的维护情况、许可、扩展与源码位置能力，优先复用成熟 parser/writer。
2. 实现 Markdown 解析到 Caret 规范树的映射及 Caret 树到选定方言的导出。
3. 对降级与拒绝场景生成可定位的诊断；避免覆盖当前会话。
4. 用可观察输入、文档结构、导出文本和失败副作用覆盖测试；独立评审后更新本任务记录。

## 预计改动

新增格式适配代码与 Rust 集成测试；必要时在 `caret-doc` 或 `caret-app` 增加稳定 API。禁止将源格式 AST 暴露为规范文档模型。

## 验收标准

- [ ] 所有 Caret 支持的文档语义均可从声明支持的 Markdown 语法导入并导出；表格、公式、图片及嵌套结构不降格或遗漏。
- [ ] 输入版本/扩展范围与导出方言明确固定；源格式额外能力按损失报告确认或拒绝。
- [ ] Caret 扩展与 Markdown 回退内容由版本和摘要绑定；回退被外部改动时产生可见冲突，不静默以扩展覆盖。
- [ ] 不支持结构有可定位诊断；可能丢失内容时必须先获确认或拒绝。
- [ ] 解析失败不会替换当前会话；导出失败不会留下半成品目标文件。
- [ ] 测试验证结果和副作用，不断言私有 parser 实现细节。
- [ ] 独立评审和真实命令结果记录在下表。

## 风险与回退

Markdown 方言存在扩展差异。通过固定方言、显式报告扩展及保留原文件来控制；失败时不安装导入结果。
