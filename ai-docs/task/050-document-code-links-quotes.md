## 目标与背景

为 Markdown 核心语义及后续文档交换补齐规范文档结构：行内代码、代码块、块引用、超链接，以及嵌套和多段列表项。先建立可编辑的 Caret 自有节点与行为，之后才开始 Markdown 文件导入导出。架构边界见[文档格式导入与导出](../architecture/editor/document-interchange.md)。

## 范围与非目标

- 为行内代码和多行代码块定义持久化语义；代码按惰性文本处理，不执行。
- 为嵌套块引用定义结构节点和子块规则。
- 支持模型限制内的嵌套列表和多段列表项，定义跨段编辑、移动、删除及位置映射；升级现有“一项一段”约束。
- 为超链接定义可编辑目标 URI 与行内显示内容；解析外部 URI 时不自动访问网络。
- 定义节点 ID、位置路径、拆分/合并、复制粘贴、撤销重做、未知能力和 `.cdoc` 兼容规则。
- 本任务实现文档模型、命令与 Rust 行为，不实现最终布局和 Qt/QML 绘制；由 051 承接。
- 不实现图片、嵌入 HTML 或任意 Markdown 插件。

4. 用黑盒行为测试覆盖成功与失败副作用；独立评审后复验并更新记录。

## 预计改动

`caret-doc` 节点及序列化、`caret-engine` 编辑命令和必要的 `caret-app` 服务接口；不让 QML 自行解释文档语义。

## 验收标准

- [ ] 行内代码、代码块、块引用和链接有稳定、版本化的 Caret 语义表示。
- [ ] 这些结构可创建、编辑、保存重开、复制粘贴和撤销重做。
- [ ] 块引用支持嵌套；列表支持模型限制内的嵌套和多段列表项；代码文本按字面呈现；链接编辑不触发网络访问。
- [ ] 拆分、合并、移动和删除返回正确的位置映射；失败操作不改变文档和选区。
- [ ] 未知节点和必需能力遵循文档模型的兼容规则。
- [ ] Rust 黑盒测试验证可观察行为；独立评审和验证结果已记录。

## 风险与回退
