## 目标与背景

当前数学光标高度可能随焦点附近的字形变化。上标、下标、分数、根式和普通数学字形的排版盒高度不同，导致同一编辑会话中的光标视觉高度跳变。用户期望与普通文本相同的稳定行级光标高度。

该契约覆盖行内公式、显示公式块、Align 单元格，以及数学源码、MathTree 结构编辑和 MathText 文本流焦点。公式布局仍决定光标的水平位置和垂直定位；焦点字形的局部包围盒不得单独决定光标高度。稳定高度应选用明确的宿主行度量，并验证空占位符、上下标和多行结构。

## 范围与非目标

- 核对普通文本 caret 高度的权威度量和所有数学 caret geometry 生成路径。
- 统一所有数学宿主与编辑分支的光标高度，同时保留各数学结构所需的 x/y 位置、脚本定位和行/单元格选择。
- 覆盖基线字形、上下标、`\frac`、`\sqrt`、`\text`、空公式占位符及 Align 多行。
- 不改变数学公式本身的排版、上下方向键候选、光标横向命中、占位符大小或普通文本 caret 行为。
- 不以系统输入法提示或光标闪烁/可见性控制代替几何高度契约。

## 前置条件与待决策

- 先从普通文本 layout snapshot 确认稳定光标高度使用的行度量，再确定数学 caret 对应的等价度量。
- 确认行内公式使用的宿主文本行、显示公式的 equation 行以及 Align cell 行度量如何在布局接口中表达；不能用数学字形局部 bounding box 作为高度。
- 如用户要求的“和普通文本一样”与宿主行高在数学对象溢出时冲突，先以测试显示差异并记录决策，不默默裁切公式或偏移光标。

## 实施步骤

1. 绘制普通文本与全部数学宿主/分支的 caret geometry 数据流，确认 x、y、height 分别由何处提供。
2. 为相同宿主、不同焦点字形增加 geometry 行为测试，先复现高度差异。
3. 让数学 caret 高度使用稳定的宿主行级度量；保留数学布局给出的插入位置与视觉亲和性。
4. 覆盖 inline、equation、align、MathTree、MathText、source 和空占位符，检查布局快照、ViewModel 与 Canvas 投影。
5. 运行相关 Rust/native/Qt 测试和可用的桌面验证；由 subagent 独立审查最终 diff。

## 预计改动

预计涉及 `crates/caret-engine/src/page_glyphs.rs`、数学布局/页面 caret geometry、`crates/caret-app/src/document_view/`、`native/viewmodels/document/`、`native/canvas/document_canvas/` 及对应测试。具体以数据流审计为准，避免在多个层重复存储高度策略。

## 风险与回退

统一高度可能导致复杂公式行中的光标与普通字形看起来不对齐，或在紧凑行高下裁切。使用宿主行度量并分别验证行内公式、块公式和 Align；若出现裁切，修正行级布局度量，不恢复依赖当前焦点字形的高度跳变。
