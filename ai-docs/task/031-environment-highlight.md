## 目标与背景

光标所在环境应获得轻量背景高亮，帮助用户识别结构边界。行内环境、块级环境和命令输入提示使用三种独立背景颜色。高亮是视图状态，不写入文档、主题快照或保存文件；环境内容原有的字符颜色和底纹仍须可见。

## 范围与非目标

由 Rust 当前光标位置解析最内层 `EnvironmentNode` 的稳定 ID、作用域和范围，并提供给画布作为视图叠加。行内环境使用 `color-inline-environment-highlight`，块级环境使用 `color-block-environment-highlight`；命令查询/补全层使用 `color-command-prompt`，由 009 接入。命令提示可与环境高亮同时显示，二者几何和颜色互不覆盖。离开环境或光标移到其他环境时清除旧范围。缩放、分页、换行和滚动后，高亮几何必须与当前 LayoutResult 对齐。

行内、块级、多行环境与命令提示复用 `HighlightBackground` 的背景外观；每种作用域独立提供布局几何和主题颜色。行内范围不加水平留白，命令提示按输入控件需要保留水平内边距。

不包含环境创建、环境样式编辑、主题定制面板或把高亮序列化为文档格式。

## 前置条件与待决策

027 的布局快照、稳定位置和画布绘制链路可用；010 已提供 `Section`/`Showcase` 的块布局及结构范围。开始实施时核对 Rust 可返回的环境范围与现有视图 DTO；不得在 QML/C++ 复制文档树遍历逻辑。

## 实施步骤

1. 核验 Rust 光标路径和环境节点范围 API，补齐最小只读视图 DTO。
2. 将当前环境标识和范围接入画布叠加，复用同代布局几何。
3. 覆盖嵌套、离开环境、光标移动、分页、滚动、缩放和 stale generation。
4. 验证高亮不改变保存结果，并完成独立评审。

## 预计改动

`caret-engine` 环境范围查询、FFI/ViewModel 只读 DTO、QML/Canvas 叠加和相应单元/窗口测试。具体文件以实现时核验为准。

## 验收标准

- [ ] 光标所在最内层环境唯一决定高亮范围；无环境时不显示高亮。
- [ ] 行内环境、块级环境和命令提示分别使用独立 GUI 主题 token；默认、浅色和深色主题都提供有效颜色，环境高亮不进入文档排版主题。
- [ ] 块级容器高亮与行内文字范围高亮符合环境 scope，嵌套时仅突出最内层。
- [ ] 分页、换行、滚动和缩放后，高亮与当前 generation 的排版几何一致；旧 generation 不覆盖新范围。
- [ ] 环境内容现有文字颜色和底纹仍可绘制，高亮不会写入 `.cdoc` 或改变文档 generation。
- [ ] 关键环境路径、空范围、失效位置和 stale generation 有测试；真实窗口验收与独立评审通过。

## 风险与回退

环境范围可能跨多页或由多个行片段组成；画布应使用布局快照提供的片段几何，不在 UI 层重新排版。若查询失败，清除高亮并保留正文，不得显示过期范围。
