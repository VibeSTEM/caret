# 注释与接口契约

更新日期：2026-10-24。

注释解释约束和取舍：单位、所有权、线程、失效条件。不把代码逐句翻译一遍。公共 API 写输入、输出、可恢复失败和资源所有者。简单 getter 不填空字段。

项目文档和解释性注释用中文。标识符保持原文。移植来的代码保留已有注释里的技术事实；把 `panta` 名字改成 `caret` 时，一起改注释里的 crate 名和模块名。第三方源码不改写注释语言。

新增或拆分的 Rust 源文件第一行用 `//!` 简要说明模块职责；拆分出的 C++/QML 实现文件第一行用中文注释说明该文件负责的功能。说明职责与边界，不逐句复述实现。

## 语言

- Rust 公共 API 用 `///`。公开 unsafe 必须有 `# Safety`。每个 unsafe 块用 `// SAFETY:` 说明前提为何成立。
- C++ 公共头用简短的文档注释，契约写在声明处。实现文件只用 `//` 补充局部原因。
- `#include` 由 `.clang-format` 和 `.clang-tidy` 排序：主头单独成块，其余按字母序。include-cleaner 用来找直接依赖。不能拆开的系统伞头才在该行登记例外，并写明原因。
- QML 的公共属性和信号旁写输入和绑定约束。不必给每个布局属性加注释。
- CMake 注释说明非默认选项和生成步骤的原因。生成的 CXX 和 Qt 文件不手工加注释。

## 标记

后续工作写成 `TODO(task NNN): 原因；完成条件`，NNN 必须是真实任务。挡住当前验收的缺陷不能靠 TODO 算完成。

兼容入口使用[代码生命周期](code-lifecycle.md)里的 `COMPAT(...)`。普通 TODO 不能代替它。
