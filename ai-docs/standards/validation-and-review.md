# 验证与评审

更新日期：2026-10-27。命令见[测试规范](testing.md)，提交见[提交规范](commits.md)。

## 范围

task 先写触发条件、预期行为和非目标。实现不混入无关重构或依赖升级。长期决定同步到架构或规范。

## 最小验证

| 改动 | 验证 |
| --- | --- |
| 文档和忽略规则 | 链接、索引、忽略规则的正反样例 |
| 领域逻辑 | 关键输入、失败和状态 |
| 路径 | 六类根、越界 `..`、尚不存在的写入目标、`qrc` 拒绝 |
| DSL | 合法样例、未知 kind、重复键、格式化稳定 |
| 构建和依赖 | 干净构建、增量构建、失败码 |
| FFI | 所有权、错误、关闭后的迟到回调 |
| QML 组件和对话框 | qmllint、token 绑定、键盘焦点、真实窗口 |
| 存储 | 往返、不兼容版本、写到一半的失败 |

覆盖率门槛见测试规范，它不代替行为断言。可达逻辑补测试。每个排除都记录原因和复查条件。

修复故障时优先加能复现问题的最小用例。性能声称附输入规模、机器和测量方式。

## 评审

看行为是否符合 task，失败是否保留有效状态，所有权和线程是否写清，产物是否在构建树，文档是否同步。清理检查覆盖旧符号、构建注册和配置。兼容标记按[代码生命周期](code-lifecycle.md)复核。

评审结论记在 task 中，不直接当成通过证明。

## 独立评审与委派

- 非平凡任务交付前做独立评审，对照需求、风险和完整 diff。拼写、格式或单行修复除外；用户要求时仍要评。
- 动到排版结果或缓存键时，确认基准没有退化，键也没有扩散。
- 覆盖率缺口按[测试规范](testing.md)拆给 subagent。不为了数字补断言或豁免行。
- 能拆成互不重叠的产出时可以并行。不让两个代理同时改同一处。没有独立审查要求的小改动，不为形式启动 subagent。
- Subagent 默认使用 `gpt-6.1-terra`，推理强度为 medium；独立代码评审使用 `gpt-6.1-sol`，推理强度为 medium。用户指定模型或强度时，以用户为准；其他厂商使用当前模型。委派前写明模型和推理强度。
- 委派说明写明目标、范围、路径、验收条件、要运行的检查，以及只读还是允许修改。独立评审默认只读。
- 报告写明问题、文件和行号、触发条件和影响。没有发现时写检查范围和限制。主代理判断发现是否成立，并负责修复、验证和更新文档。
- 等待评审时继续做不依赖结论的工作。修复后重跑受影响的检查。只有范围无法缩小或明确要求完整验收时才跑全量测试。
- Subagent 不提交、推送、创建或合并 PR，也不对外沟通，除非用户明确授权。

仓库还没有这些命令时，文档改动的验证是链接和检索，不伪造测试通过。
