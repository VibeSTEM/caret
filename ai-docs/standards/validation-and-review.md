# 验证与评审

更新日期：2026-10-29。验证命令和范围见[测试规范](testing.md)；提交与分支规则见[提交规范](commits.md)。

## 开始前

- 对照 task 确认触发条件、预期行为、验收标准和非目标。实现只覆盖必要范围；长期有效的行为决策同步到架构或规范。
- 先找负责该行为的权威状态和模块，再检查数据经过的边界。不要在 Qt/QML 重复实现 Rust 领域规则，也不要为未来假设增加无关抽象。
- 根据改动范围选择验证项。优先运行能覆盖改动和直接消费者的最小命令；完整 workspace 检查用于影响范围无法缩小、公共边界变化或明确要求完整验收的情况。命令、环境、结果和未覆盖范围记入 task。

## 验证要求

修复缺陷时先添加可复现问题的用例。测试断言用户可观察的行为及失败后的有效状态，不以覆盖率数字代替行为验证。测试排除项需记录理由和复查条件。

| 改动范围 | 至少检查 |
| --- | --- |
| Rust 领域逻辑、文档模型或编辑 | 正常输入、边界输入、失败原子性、状态与不变量；直接消费者的测试 |
| 文件、序列化或兼容性 | 往返、无效/未知数据、迁移边界；写入失败不破坏原文件 |
| FFI、线程或异步任务 | 所有权、错误传播、关闭后的迟到结果、generation/revision 过期结果不会覆盖新状态 |
| Qt/C++/QML | 属性通知和绑定、焦点/输入、键盘操作、组件格式与 lint；涉及窗口行为时做可用的窗口验证 |
| 用户可见翻译 | 提取 QML/Qt 翻译源；逐个核对所有支持 locale 的 `.pa` 条目、上下文、占位符和完成状态；验证生成 QM 可加载 |
| 命令、路径或 DSL | 合法与非法输入、边界路径/语法、错误码及失败后的状态 |
| 性能或排版 | 代表性输入、基线对比、机器/构建配置/测量方式；注明尚未验证的瓶颈 |
| 文档、索引或忽略规则 | 链接和引用有效；新规则同时检查应忽略与应保留的样例 |

### 状态机与跨层状态

凡是新增或修改状态、状态标签、按钮可用性、关闭流程、异步完成结果或持久化行为，都要检查完整状态链，而不只检查状态字段：

1. **权威来源**：领域状态由 Rust 类型/服务权威持有；Qt 本地交互状态按架构约定由 Qt 管理。不得维护第二份权威状态；ViewModel 可保留同步更新的只读投影。
2. **迁移**：列出触发事件、前置状态、目标状态及拒绝条件；覆盖成功、失败、取消、重复事件和无变化事件。失败时保留的文档、路径、保存点和错误信息要符合契约。
3. **跨层传播**：对跨层状态，验证权威状态 → FFI 快照/结果 → ViewModel 属性及通知 → QML 绑定的每一段。确认变更后通知确实发出，派生属性（如标题、脏状态、命令可用性）与权威状态一致。
4. **异步与重入**：检查保存期间继续编辑、会话关闭后回调、旧 generation/revision 返回、重复请求和乱序完成；过期结果不得覆盖新状态或错误地关闭窗口。
5. **可验证性**：为每条关键迁移写命令级或组件级测试。若只能人工验证，记录步骤、平台和结果；不能把未执行的验证写成通过。

纯视觉 token 不需要 Rust 状态机；但用户偏好和持久化设置按[分层规范](layering.md)归属，并验证更改的通知与生效范围。

## 评审清单

基于完整 diff 对照 task 检查：

- 行为、错误处理、兼容约束和状态迁移符合文档；失败不会丢失有效状态。
- Rust、FFI、Qt、QML 职责清晰；异步、所有权、线程和 revision/generation 校验正确。
- 检查模块间是否存在不必要的耦合：依赖方向是否符合分层，单个功能是否需要同时改动多个不相关模块，状态或策略是否被重复持有，组件是否依赖实现细节而非稳定接口；若有耦合，说明它是必要边界还是应拆分/反转依赖。
- 检查 crate 边界是否合适：只有当能力拥有稳定且独立的职责、需要独立复用/发布/依赖约束，或确实需要编译与安全边界时才考虑单独 crate；若拆分只为缩短文件、移动代码或组织目录，应留在现有 crate 的模块中。记录拆分带来的依赖、API、构建和维护成本，并与收益比较。
- 模块按独立职责组织，没有膨胀文件、重复实现、无用抽象或散落的魔法值。Rust 文件结构遵循[仓库文件结构](repository-hygiene.md#模块文件结构)。
- 清除孤儿源码、资源、测试、未使用依赖和重复实现。删除前交叉检查调用点、Cargo/CMake 注册、QML/Qt 元对象、FFI、资源及生成器入口；仅凭文本搜索不到不能判为死代码。
- 构建、测试、格式、lint、文档和索引与改动一致；排版或缓存变更没有造成无意的范围扩散或性能退化。
- 翻译变更保持源码与所有受支持语言同步：用锁定 Qt 工具 `lupdate` 从实际 QML/Qt 源码提取消息，与 `.pa` 中的 context/source 对照；新增或修改的用户可见文案在每个受支持 locale 中都有正确翻译并标记 `st: finished`。检查 `%1`、`%n` 等格式占位符逐字对应、上下文未漂移、没有失效或重复条目；新增语言同时更新 Rust 语言目录、资源构建和可加载 QM 验证。不能只检查 `.pa` 语法或英文目录，也不能把系统 locale 可识别视为应用已支持该语言。

评审记录写明检查的提交/diff 范围、发现的问题及修复状态、未确认的风险。评审结论不是验证通过的替代品。

## 独立评审与委派

- 非平凡改动在交付前由未参与实现的 subagent 独立检查完整 diff；纯拼写、格式或单行修复可免。用户明确要求评审时始终执行。
- 独立评审使用 `gpt-6.1-sol`，推理强度 medium；其他适合委派的任务使用 `gpt-6.1-terra`，推理强度 medium。
- 委派说明写清目标、范围、可读/可写权限和交付格式；独立评审只读。避免多个代理同时改同一文件。subagent 不提交、推送、创建/合并 PR 或对外沟通，除非用户授权。
- 评审报告应给出问题、位置、触发条件和影响；无发现时也说明检查范围与限制。主代理负责判断、修复、复验和更新 task。修复后重跑受影响的检查。

仓库尚无对应自动化命令时，只报告实际完成的检查，不伪造测试结果。
