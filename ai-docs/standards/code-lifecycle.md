# 代码清理与兼容例外

更新日期：2026-10-30。适用于自有代码、构建脚本、配置、资源和测试。

## 无死代码

Git 保存历史。当前树只保留仍支持的行为。替换功能的同一次 commit 删除旧实现和失效引用。

一起检查：无用的类型和文件、旧入口、只服务旧实现的依赖和资源、已经没有对象的测试。仍在验证受支持行为的测试迁到新实现，不借清理删掉。

不用注释块、`#if 0`、`old/`、`backup/` 或 `allow(dead_code)` 把旧实现留在树里。Qt、QML、FFI 和生成器真正用到的符号，要有入口证明，不能只因为文本搜索不到就删除。

## 兼容

默认只实现当前选定的行为。不添加猜测未来的双版本分支或旧名字别名。不支持的输入返回可定位错误，并保留用户仍有效的数据。持久化格式的未知字段与能力按[`.cdoc` 存储格式](../architecture/editor/document-model/document-storage.md)处理：未知可选字段往返保留，未知必需能力拒绝写入。

确有现实需求时，先写进所属 task，再在每个兼容入口旁标记：

```text
COMPAT(task NNN; remove-task MMM): 适用版本和原因
```

C++、Rust 和 QML 用 `//`，Python 和 CMake 用 `#`。标记写明触发条件、失败方式、验证入口，以及可以判断的删除条件。兼容代码留在最小的适配入口。

从仓库根搜索：

```sh
rg -n -F 'COMPAT(' .
```

文档里的示例和运行代码要分开看。每次提交说明删了什么，或写明没有废弃项。
