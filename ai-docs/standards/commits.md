# 提交规范

更新日期：2026-10-24。

一次 commit 是一个可以核对的行为单元：包含这次目的所需的代码、测试、配置、锁文件、文档和 task。不提交已知损坏的中间状态。一个 task 可以分多次提交；一次提交原则上属于一个主 task。

## 提交前

1. 行为符合标题。
2. 替换实现时删掉旧调用、旧依赖和失效文档。兼容例外见[代码生命周期](code-lifecycle.md)。
3. 在即将提交的内容上运行检查。部分暂存时确认暂存内容自身成立。
4. 受影响的 task 和索引一起更新。状态没变时不必为了制造 diff 重写索引。
5. 暂存 diff 里没有无关产物。

从 panta 移植时，正文写来源仓库和 commit。

## 消息

```text
<type>(<scope>): <具体行为>

说明触发条件、结果和必要取舍。简单变更可以省略这段。

Task: NNN
Validation: 实际检查及结果；不能执行时说明原因
Cleanup: 删除项，或本次无废弃项
Compat: none，或例外标记、原因与清理任务
```

type 使用 `feat`、`fix`、`refactor`、`cleanup`、`build`、`test`、`docs`、`ci`、`chore`、`revert`。scope 使用实际模块，例如 `docs`、`qml`、`ffi`、`build`。没有所属 task 时，`Task:` 写“无”，并说明原因。

破坏既有接口时，在冒号前加 `!`，正文说明调用方和迁移方法。不为了避免这个标记而加兼容层。

不改写已经共享的历史，除非当前工作明确要求。
