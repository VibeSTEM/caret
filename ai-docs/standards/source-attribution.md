# 源码署名

更新日期：2026-10-30。

## 目的与含义

源码署名是维护者指定的统一项目署名标识，不表示署名者独自编写文件中的全部代码，也不替代 Git 历史中的具体贡献记录。署名姓名放在源码文件中，不在本规范或协作指南中固定记录。署名不是版权声明或许可证条款，许可证仍以仓库根目录的 `LICENSE` 为准。

文件头同时标明仓库开源协议：根目录 `LICENSE` 当前为 Apache License 2.0，源码使用 SPDX 标识 `Apache-2.0`。SPDX 行标明许可证，不是作者署名。

同一作者的署名在源码中保持统一，不加入邮箱、日期、版本号、角色或逐文件变化的作者名单。

仓库中经维护者确认的第一方源码署名样例是唯一标准，新增或重构文件必须照样例使用同一署名值，不按单次任务或实现者另行选择。若仓库尚无已确认的源码署名样例，实施前向项目维护者确认并建立首个样例。不得把文档占位符、Git 提交名或代理身份当作署名写入源码。

## 文件范围

新增或重构纳入范围的第一方生产 Rust、QML、C++ 源文件必须使用署名，包括 `crates/`、`native/` 与 `qml/` 下对应的手写实现。测试代码、性能基准和示例暂不纳入“核心代码”范围；若希望给这些文件也署名，应在批量修改前明确扩展范围。以下内容不加署名：

- Qt/CMake/Rust 等工具生成的源码和构建产物。
- 第三方或 vendored 源码。
- 纯数据夹具、快照、代码片段及不作为本项目实现维护的示例。

本标准采纳后，新建或重构文件从一开始遵守本规则；既有文件批量补署名时单独提交机械改动，不与行为变更混在一个提交中。

## 三种源码格式

各语言均使用普通 `//` 行注释，文件头按以下次序排列：文件职责说明、`// SPDX-License-Identifier: Apache-2.0`、`// 署名：<作者署名>`。示例中的 `<作者署名>` 是说明性占位符，不能原样写入源码；署名值按“目的与含义”中的规则确定。根据各语言已有文件头约定放置：

### Rust

保留模块职责说明作为第一行，在其后添加署名。模块职责继续使用 `//!`，署名不使用文档注释，避免将署名展示为 Rust API 文档内容。

```rust
//! 管理文档编辑会话中的行内格式命令。
// SPDX-License-Identifier: Apache-2.0
// 署名：<作者署名>
```

### QML

文件功能说明仍放第一行，随后依次放 SPDX 行和署名行，再写 import 和 QML 声明。

```qml
// 显示文档命令候选并处理候选键盘选择。
// SPDX-License-Identifier: Apache-2.0
// 署名：<作者署名>

import QtQuick
```

### C++

实现文件或头文件的中文职责说明仍放第一行，随后依次放 SPDX 行和署名行，再写 `#pragma once`、include 或声明。

```cpp
// 处理文档画布的输入法预编辑事件。
// SPDX-License-Identifier: Apache-2.0
// 署名：<作者署名>

#include "document_canvas.hpp"
```

## 维护规则

- 署名放在文件级职责说明之后、代码内容之前，不放在每个函数、类型或代码块上。
- SPDX 行应与根目录许可证一致；本仓库现行值为 `Apache-2.0`。许可证变化时统一更新规则和源码标识，不自行添加第二个许可证选项。
- 不在自动生成文件或第三方代码中追加署名，也不修改已有的第三方许可证/版权头。
- 文件职责说明仍按[注释规范](comments.md)编写；署名不代替模块说明、API 契约或 `SAFETY` 注释。
- 新增的项目贡献者不通过改写所有文件署名来记功，具体贡献由版本控制历史记录。
- 后续若需要正式版权声明、组织法律名称或多作者归属，先单独确定法律文本与适用范围，再更新许可证/版权策略；不要把本署名行直接解释为版权转让或独占声明。
